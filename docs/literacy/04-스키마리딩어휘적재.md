# Phase 3-2 — 레벨 체계 전환 및 스키마리딩 어휘 자료 적재

## 0. 시작 전에

`docs/literacy/00-현황.md`, `01-스키마.md`, `03-교재어휘-현황.md`를 먼저 읽어라.
작업 브랜치는 `literacy-db`다.

이번 단계는 **① 레벨 체계 전환(스키마 변경)** 과 **② 신규 자료 적재** 두 가지를 한다.
반드시 ①을 먼저 끝내고 ②로 넘어간다.

## 1. 배경 — 왜 레벨 체계를 바꾸는가

Phase 3에서 `grade_level`을 1~12(초1~고3) 학년 단위로 정의했다. 그러나 실제 확보된 자료의 등급은 학년 단위가 아니라 **2개 학년을 묶은 단계 단위**로만 존재한다. 없는 정밀도를 있는 것처럼 저장하면, 이후 등급 산정과 문항 출제에서 잘못된 정확도를 전제하게 된다.

따라서 **레벨 0~6** 을 새로운 기본 기준으로 도입한다.

| level | 학년 | 비고 |
|---|---|---|
| 0 | 초1~2 | 이번에 신설 |
| 1 | 초3~4 | |
| 2 | 초5~6 | |
| 3 | 중1~2 | |
| 4 | 중3 | |
| 5 | 고1~2 | |
| 6 | 고3 | |

**`grade_level`은 삭제하지 않는다.** 교재 어휘처럼 학년이 명확한 자료는 그 정보를 잃으면 복구할 수 없다. 두 컬럼을 함께 유지하고, 실제 운용 기준은 `level`로 한다.

## 2. 절대 금지 사항

- 교재DB(`momo_book_db/momo_book.db`)는 이번 단계에서 **열지 않는다.** 필요 없다
- 기존 라우터·에이전트 파일을 수정하지 않는다
- 서버(`34.158.219.100`)에 접속하지 않는다
- 절대경로 하드코딩 금지
- **`grade_level` 컬럼을 삭제하지 마라**
- 기존 2,884건(속담·관용구)과 821건(교재 어휘)의 데이터를 손상시키지 마라
- 사전(krdict) 전체 어휘 5만 건을 적재하지 마라. 이번 범위가 아니다
- 검수 UI, 퀴즈 생성 코드를 만들지 마라

## 3. 작업 ① — 스키마 변경

### 3-1. 마이그레이션 스크립트

`app/literacy/migrations/002_add_level.py` 를 새로 만든다. `001_initial.py`의 패턴을 따른다.

- `terms` 테이블에 `level INTEGER` 컬럼 추가
- `level`에 인덱스 추가
- 멱등성: 이미 컬럼이 있으면 아무것도 하지 않고 그 사실을 출력
- **실행 전 DB 파일을 백업**한다 (`data/literacy.db.bak-YYYYMMDD-HHMMSS`). 백업 파일은 커밋하지 않는다
- `app/literacy/models.py`의 `Term` 모델에도 `level` 필드 추가

### 3-2. 기존 데이터의 level 채우기

같은 마이그레이션에서 기존 행의 `level`을 채운다.

**교재 어휘(`source='momo-textbook'`, 821건)** — 기존 `grade_level`로부터 변환한다.

| grade_level | level |
|---|---|
| 1, 2 | 0 |
| 3, 4 | 1 |
| 5, 6 | 2 |
| 7, 8 | 3 |
| 9 | 4 |
| 10, 11 | 5 |
| 12 | 6 |

`grade_level`은 그대로 둔다.

**속담·관용구(`source='krdict'`, 2,884건)** — `level`을 NULL로 둔다. 등급 정보가 없다. 이후 별도 단계에서 매긴다.

## 4. 작업 ② — 신규 자료 적재

원본 3개 파일을 `raw/schema-reading/` 에 복사해 보관한다(커밋하지 않음).

### 4-1. 학습 도구어 사전

파일: `학습_도구어_사전_레벨1_6__0925최종버전___1_.xlsx`

- 시트 `Level1`~`Level6`, 각 시트가 곧 레벨 1~6
- **헤더가 3행째에 있다.** `header=2`로 읽는다. 그 위 2행은 제목·빈 행
- 읽은 뒤 첫 행이 다시 `레벨/주차/어휘/...` 인 경우가 있으니 제거한다
- 컬럼: 레벨 / 주차 / 어휘 / 의미 / 품사 / 유의어·반의어
- **`Level4` 시트만 컬럼이 7개다.** 다른 시트는 `유의어/반의어`가 한 컬럼인데 Level4는 `유의어`와 `반의어`로 분리돼 있다. 컬럼 개수로 분기 처리하라
- 의미·품사·유의어는 `|` 로 여러 값이 구분되어 있다
- 유효 행 약 2,035, 고유 어휘 약 1,324

저장값:

| 필드 | 값 |
|---|---|
| `category` | `어휘` |
| `headword` | 어휘 |
| `definition` | 의미 (`\|`로 나뉘면 **첫 번째만**) |
| `pos` | 품사 |
| `level` | 시트 번호 1~6 |
| `grade_level` | **NULL** (학년 단위 정보 없음) |
| `grade_source` | `manual` |
| `source` | `schemareading-tooldict` |
| `license` | `자체제작` |
| `external_id` | `L{레벨}-{원본 행번호}` |
| `review_status` | `검수전` |

- 두 번째 이후 의미는 `examples`에 `source='tooldict-sense-N'`으로 저장
- 유의어·반의어는 `examples`에 `source='tooldict-synonym'` / `'tooldict-antonym'`으로 저장. 버리지 마라

### 4-2. 스키마 어휘 목록

파일: `스키마_어휘_목록_레벨2_5_완성_.xlsx`

- 시트: `사회 스키마`, `과학 스키마`, `인문철학스키마`
- 헤더는 첫 행에 정상적으로 있다
- `단어명`이 비어 있는 행은 건너뛴다. **인문철학 시트는 645행 중 28행만 유효하다. 정상이며, 채우려 하지 마라**
- `단계` 값은 `1단계`~`6단계` 형식. 앞 숫자가 곧 레벨
- `정의` 채움률: 사회 73%, 과학 59%. **비어 있으면 NULL로 두고 채우려 하지 마라**

저장값:

| 필드 | 값 |
|---|---|
| `category` | `어휘` |
| `headword` | 단어명 |
| `definition` | 정의 (없으면 NULL) |
| `sense_category` | 중분류 (없으면 대분류) |
| `subject_category` | 대분류 |
| `level` | 단계 앞 숫자 |
| `grade_level` | **NULL** |
| `grade_source` | `manual` |
| `source` | `schemareading-schema` |
| `license` | `자체제작` |
| `external_id` | `{시트약칭}-{번호}` (예: `social-1`, `sci-1`, `phil-1`) |
| `review_status` | 정의 있으면 `검수전` / 없으면 `보류` |
| `note` | 소분류, 주차 |

`sense_category`는 반드시 채워라. **퀴즈 오답 생성이 이 필드에 의존한다.** 이 자료의 교과 기준 분류는 krdict 범주보다 오답 생성에 유리하다.

### 4-3. 중복 처리 규칙

**같은 `source` 안에서만 중복을 병합한다. 서로 다른 `source` 사이에서는 병합하지 마라.**

- **같은 source 내(나선형 반복, 약 613건)**: 최저 레벨을 채택하고, `note`에 `나선형 반복: L2,L4,L6` 형식으로 전체 등장 레벨을 기록한다. 반복 자체가 교육적 설계이므로 이력을 지우지 마라
- **source 간(약 35건)**: 병합하지 않는다. 별도 행으로 각각 적재한다

source 간 병합을 금지하는 이유: 조사 결과 이 35건 중 대다수가 **동형이의어**다. 예를 들어 "교류"는 학습도구어에서 일상적 의미(레벨1), 스키마 물리에서 교류 전기(레벨5)다. "위상"(일반/물리 phase), "초점"(일반/광학), "전자"(앞의 것/電子), "지각"(늦음/地殼)도 마찬가지다. 병합하면 물리 용어가 초등 어휘가 되는 오류가 발생한다.

`UNIQUE(source, external_id)` 제약이 이미 이 동작을 보장하지만, 파싱 단계에서 임의로 dedup 하지 않도록 주의하라.

## 5. 실행 순서

### 5-1. 스키마 변경 먼저

`002_add_level.py` 실행 후 아래를 확인하고 보고한다.

- `level` 컬럼 생성 확인
- 교재 어휘 821건의 `level` 분포 (0~4에 분포, 5·6은 0건이어야 함)
- `grade_level`이 보존되었는지 확인
- 속담·관용구 2,884건의 `level`이 NULL인지 확인
- 마이그레이션 재실행 시 안전한지 확인

### 5-2. dry-run — 여기서 멈춰라

적재 전에 다음을 출력하고 **승인을 기다려라.**

1. 자료별·레벨별 건수 표 (tooldict 1~6, schema 1~6)
2. 정제 전후 비교 20건
3. 같은 source 내 나선형 반복 건수와 예시 20건
4. source 간 동일 표제어 목록 전체 (약 35건) — 병합하지 않고 둘 다 적재됨을 확인
5. `definition`이 비어 있는 건수 (자료별)
6. `sense_category` 채움 비율
7. 표제어에 공백·괄호·개행 등 이상 문자가 포함된 항목 전체 목록
8. Level4 시트의 7컬럼 분기 처리 결과 샘플 5건

승인 전에 적재하지 마라.

### 5-3. 적재

승인 후 실행한다. `collection_runs`에 자료별로 이력을 남긴다.
`source='schemareading-tooldict'`, `'schemareading-schema'`. try/finally로 마감한다.

## 6. 검증

1. `source`별 행 수: `schemareading-tooldict` 약 1,324, `schemareading-schema` 약 2,053. **예상과 차이가 있으면 원인을 설명하라**
2. `level`별 전체 분포 (0~6). 각 레벨에 데이터가 있는지 확인
3. `level`이 NULL인 행 수 = 2,884(속담·관용구)와 일치하는지
4. `sense_category` 채움 비율 (source별)
5. **재실행 시 행 수 증가 없음**
6. source 간 동형이의어가 각각 별도 행으로 살아있는지 확인 — "교류", "위상", "초점", "전자", "지각"을 조회해 각각 2행씩 나오는지, 뜻풀이가 서로 다른지 출력
7. 무작위 10건의 `headword`/`definition`/`level`/`source`/`note` 전문 출력
8. `examples` 행 수 증가분 보고 (유의어·반의어·추가 의미)
9. `/literacy/health`의 `terms_count` 확인
10. `git status`
