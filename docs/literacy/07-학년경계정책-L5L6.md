## 왜 002_add_level.py를 고치지 않고 문서로만 남기는가

`_GRADE_TO_LEVEL` 매핑은 `grade_level`(1~12, 초1~고3)을 `level`(0~6)로 변환하는
**이미 실행 완료된** 로직이다. 옛 기준으로는 `grade_level=10,11(고1,고2)→level5`,
`grade_level=12(고3)→level6`이었다. 새 기준(L5=고1, L6=고2~3)대로라면
`grade_level=11(고2)`는 `level6`이어야 하지만, 이미 `momo-textbook` 소스
821건 중 `grade_level=10,11`인 행은 전부 `level=5`로 저장돼 있다.

**이번 정책 갱신은 이 기존 저장값을 소급 재분류하지 않는다** — 사용자 지시
("기존 AI 판정과 저장된 레벨 값은 이번 수정으로 재분류하지 말 것")에 따라,
코드는 "앞으로" 올바른 기준을 쓰도록만 고쳤다. 즉:

- `momo-textbook` 821건의 기존 `level` 값(마이그레이션이 이미 백필한 값)은
  그대로 둔다 — 옛 경계 기준으로 저장돼 있다는 사실만 이 문서에 기록한다.
- 앞으로 새로 판정되는 속담·관용구·사자성어(`auto_review_level.py` 재실행분)만
  새 경계(L5=고1/L6=고2~3)를 따른다.
- 만약 향후 `momo-textbook` 821건의 `grade_level=11`(고2) 행을 `level=5→6`으로
  재분류하기로 결정한다면, 그것은 이번 작업과 분리된 **별도의 명시적 소급
  재분류 작업**으로 다뤄야 한다(사용자 승인 필요, DB 백업 필수, 영향받는 행
  수를 먼저 집계해서 보고).

## 근거 부족 판정의 보류 처리 (작업 2)

`scripts/literacy/auto_review_level.py`는 원래 "Gemini가 판정하면 사람 확인
없이 바로 `review_status='검수완료'`로 확정"하는 완전자동 설계였다(2026-09-02
사용자 결정, 스크립트 상단 docstring 참고). 이번 조사에서 실제 DB를 확인한
결과, 이 설계 그대로 지금까지 2,944건이 `grounded` 개념 없이 전부
`검수완료`로 즉시 확정돼 있었다(`grade_source='auto'`, `review_status='검수완료'`
2,944건 — 읽기 전용으로 집계만 함, 재분류하지 않음).

이번 갱신으로 Gemini 프롬프트에 `grounded`(학년 근거가 실제로 있는지 스스로
표시) 필드를 추가했다:

- `grounded=true`(또는 "해당없음" 판정): 기존과 동일하게 즉시
  `review_status='검수완료'`로 확정.
- `grounded=false`(뜻과 난이도로 대략 짐작만 한 경우): `level` 값은 저장하되
  `review_status='보류'`로 남긴다. `'보류'`는 literacy.db 전반에서 이미 "사람
  확인 전까지는 확정 아님"을 뜻하는 기존 상태값이다(krdict 폴백 동음이의/다의어
  보류, schema 정의 없는 행 보류와 같은 계열 — 새 상태값을 만들지 않았다).
- AI 응답에 `grounded` 필드 자체가 없으면(구버전 캐시/응답 누락) 안전 쪽으로
  기본값을 `False`(보류)로 둔다 — "필드가 없다고 검수완료로 확정"하는 쪽이
  더 위험하다고 판단했다.

**이 변경도 앞으로 이 스크립트를 실행할 때만 적용된다.** 과거 2,944건은
소급 재분류하지 않는다.

## 검증

`tests/test_auto_review_level_grade_boundary.py`(신규)가 다음을 확인한다:

1. `LEVEL_TABLE` 텍스트에 새 경계(고1, 고2~3)가 들어 있고 옛 경계(고1~2, 고3)가
   더 이상 없는지
2. `build_prompt()`가 실제로 만드는 프롬프트 문자열에 새 경계와 `grounded` 지시가
   포함되는지
3. 중3/고1/고2/고3 등 경계값 판정이 코드상 어느 level에 대응하는지
4. `save_result()`가 `grounded=False`일 때 `review_status='보류'`로, `True`일
   때 `'검수완료'`로 저장하는지(로컬 임시 sqlite DB에서 검증, 리포지토리
   DB는 건드리지 않음)

`tests/test_admin_level_quiz.py`(관리자 레벨 퀴즈 회귀, 71건)도 이번 수정
후 재실행해 전부 통과함을 확인했다(L5/L6 후보가 현재 0건이라 라벨 변경이
API 응답의 실질적 동작에는 영향을 주지 않는다 — L1 라벨만 assert하는
기존 테스트도 영향 없음).
