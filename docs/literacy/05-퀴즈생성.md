## 1. 목적

지금까지 쌓은 7,087건으로 **실제 문항 약 260개를 생성**한다.

이 단계의 목적은 문항 확보가 아니라 **DB가 쓸 만한지 확인하는 것**이다. 지금까지는 전부 입력 쪽 작업이었고, 출력이 실제로 교육적으로 쓸 만한지는 아직 아무도 모른다. 대량 생성 전에 소량으로 품질을 검증한다.

따라서 **양보다 진단이 중요하다.** 생성 실패나 품질 문제를 감추지 말고 그대로 보고하라.

- 교재DB, 원본 엑셀을 수정하지 않는다

- 서버(`34.158.219.100`)에 접속하지 않는다
- 절대경로 하드코딩 금지
- **API 키를 코드·로그·커밋 어디에도 남기지 않는다**
- `terms`, `examples` 테이블의 기존 데이터를 수정하지 않는다. 이번엔 **읽기만** 한다
- 검수 UI를 만들지 마라. 별도 단계다
- 260개를 넘겨 대량 생성하지 마라

## 4. 생성 대상 선정

### 4-1. 어휘 문항 210개

`category='어휘'` 이면서 `definition`이 비어 있지 않은 행에서, **레벨별로 30개씩 무작위 추출**한다 (level 0~6, 총 210개).

- `review_status='보류'`인 행은 제외한다
- `source`는 섞어도 된다 (momo-textbook / schemareading-tooldict / schemareading-schema)
- 한 단어당 1문항만 만든다
- 추출에 **고정 시드**를 사용해 재현 가능하게 하라

레벨별 30개를 채울 수 없으면 가능한 만큼만 만들고 부족분을 보고하라.

### 4-2. 속담 문항 50개

`category='속담'`에서 무작위 50개. 관용구는 이번에 제외한다.

## 5. 문항 생성 규칙

### 5-1. 형식

4지선다. 단어(또는 속담)를 제시하고 뜻풀이를 고르게 한다.

- 정답은 `terms.definition`을 그대로 쓴다. **정답 뜻풀이를 AI가 다시 쓰지 마라**
- 오답 3개를 생성한다

### 5-2. 오답 생성 원칙

**같은 `sense_category` + 같은 `level` 안에서 뽑거나, 그 범위의 개념을 참고해 생성한다.** 무작위 오답은 너무 쉬워서 변별력이 없다.

`sense_category`가 없는 항목(tooldict 등)은 같은 레벨 안에서 뽑는다.

오답은 다음 세 방향을 섞어 만든다. 기존 338문항이 쓰던 패턴이다.

- **반대 방향**: 정답과 반대되는 뜻 (가르다 → 합치거나 모아서 하나로 만들다)
- **인접 개념**: 비슷하지만 다른 뜻 (가르다 → 묶거나 연결하여 붙이다)
- **부분 오류**: 일부만 맞고 핵심이 틀림

### 5-3. 단서 노출 방지 — 이번 단계의 핵심

기존 338문항에서 발견된 문제다. **정답만 사전에서 가져오고 오답은 생성하면 문체가 갈려서, 뜻을 몰라도 정답이 보인다.**

실제 사례:
- `가르다` — 정답만 마침표로 끝나고 오답 3개는 안 끝남
- `쓰다` — 정답이 오답보다 4배 이상 김

프롬프트에 반드시 넣을 제약:

1. **종결 형태를 정답과 일치시킨다.** 정답이 `~하다.`로 끝나면 오답도 전부 `~하다.`로 끝난다. 마침표 유무까지 맞춘다
2. **길이를 정답의 ±50% 이내로 맞춘다.** 정답이 20자면 오답은 10~30자
3. **정답이 지나치게 길면(60자 초과) 정답 쪽을 줄이지 말고, 그 항목을 건너뛰고 보고하라.** 사전 정의를 임의로 축약하면 안 된다
4. 오답에 `아니다`, `않다`, `못하다` 같은 단순 부정어로만 만들지 않는다

### 5-4. 정답 위치

**1~4번에 균등하게 분포시킨다.** 생성 후 셔플하고, 실제 분포를 검증에서 보고하라.

### 5-5. 배치 처리

한 번의 API 호출에 **10문항씩** 묶어 생성한다. 같은 `sense_category` 안에서 묶으면 용어 일관성이 좋아진다.

- 실패 시 최대 3회 재시도
- 3회 실패하면 그 배치를 건너뛰고 로그에 남긴 뒤 계속 진행한다. 전체를 중단하지 마라
- 호출 사이 딜레이를 둔다

### 5-6. 예시 활용

`raw/schema-reading/어휘퀴즈DB__1___1_.xlsx`에 **선생님이 직접 만들어 쓰시던 검증된 문항 338개**가 있다. 이걸 프롬프트의 few-shot 예시로 사용하라.

- 생성 대상과 같은 성격의 예시 3~5개를 프롬프트에 포함한다
- 단, **5-3의 단서 노출 문제가 있는 예시는 고르지 마라.** 정답과 오답의 길이·종결형이 비슷한 것만 예시로 쓴다

## 6. 저장

`quiz_items` 테이블에 저장한다.

| 필드 | 값 |
|---|---|
| `term_id` | 원본 `terms.id` |
| `quiz_type` | `뜻풀이선택` |
| `question` | 문제 문장 |
| `correct_answer` | 정답 뜻풀이 |
| `distractors` | 오답 3개, JSON 배열 문자열 |
| `difficulty` | `terms.level` 값 (속담은 NULL) |
| `generated_by` | `api` |
| `model` | 실제 사용한 모델명 |
| `review_status` | `검수전` |
| `created_at` | 현재 시각 |

`collection_runs`에 이력을 남긴다. `source='quiz-gen-pilot'`. try/finally로 마감한다.

재실행 시 중복 생성되지 않도록 하라. 이미 해당 `term_id`에 `quiz_type='뜻풀이선택'` 문항이 있으면 건너뛴다.

## 7. 검수용 엑셀 출력

`data/literacy/quiz_review_YYYYMMDD.xlsx`로 내보낸다. 컬럼:

`문항ID / 레벨 / 카테고리 / 출처 / 단어 / 정답 / 오답1 / 오답2 / 오답3 / 정답위치 / 판정 / 메모`

- `판정`과 `메모`는 **빈 칸으로 둔다.** 사람이 채울 열이다
- 레벨 오름차순, 그 안에서 카테고리순으로 정렬
- 속담 문항은 별도 시트로 분리

## 8. 자동 품질 검사 — 반드시 실행하라

생성 후 아래를 계산해 보고하라. 이게 이번 단계의 실제 산출물이다.

| 검사 | 기준 |
|---|---|
| **정답 위치 분포** | 1~4번 각각 20~30%면 정상 |
| **정답 최장 비율** | 정답이 4개 중 가장 긴 문항의 비율. **40% 초과면 단서 노출** |
| **종결형 일치율** | 4개 선택지의 종결 어미가 같은 문항 비율. 높을수록 좋음 |
| **마침표 일치율** | 4개의 마침표 유무가 같은 문항 비율 |
| **길이 편차** | 정답 대비 오답 평균 길이 비율 |
| **오답 중복** | 같은 문항 안에 동일하거나 거의 같은 오답이 있는 건수 |
| **생성 실패** | 건너뛴 항목 수와 사유 |

**정답 최장 비율이 40%를 넘으면 적재하지 말고 보고하라.** 프롬프트를 고쳐야 한다.
