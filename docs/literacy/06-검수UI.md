# Phase 6 — 검수 UI 구축

## 0. 시작 전에

`docs/literacy/00-현황.md`, `01-스키마.md`, `05-퀴즈생성-결과.md`를 먼저 읽어라.
`00-현황.md`의 3절(`/review`, `/warnings` 템플릿 패턴)이 이번 작업의 핵심 참고 자료다.

작업 브랜치는 `literacy-db`다.

---

## 1. 목적

지금 검수해야 할 데이터가 세 종류 쌓여 있는데 볼 방법이 없다.

| 대상 | 건수 | 할 일 |
|---|---|---|
| 생성 문항 | 248 | O/X 판정, 메모 |
| 뜻풀이 공백 어휘 | 697 | 뜻풀이 작성 |
| 속담·관용구 | 2,884 | 레벨 부여 |

엑셀로는 감당이 안 된다. **웹에서 한 건씩 보며 판정·수정할 수 있는 화면**을 만든다.

세 가지 작업의 성격이 달라 화면도 세 개다. 다만 **레이아웃과 조작 방식은 통일**해서, 하나를 익히면 나머지도 쓸 수 있게 한다.

---

## 2. 절대 금지 사항

- 기존 라우터·에이전트·템플릿 파일을 **수정하지 않는다.** 참고만 하고 새 파일로 만든다
- 서버(`34.158.219.100`)에 접속하지 않는다
- 절대경로 하드코딩 금지
- 교재DB, 원본 엑셀을 열지 않는다. 필요 없다
- **`literacy.db` 외의 DB에 접근하지 않는다**
- 학생용 라우터(`literacy_api.py`)를 건드리지 마라. 이번 작업은 전부 관리자용이다
- 새 데이터를 수집하거나 문항을 생성하지 마라
- 프론트엔드 프레임워크를 도입하지 마라. 기존 패턴(Tailwind CDN + vanilla JS fetch)을 따른다

## 4. 공통 설계

### 4-1. 라우터

`app/routers/literacy_admin.py`에 추가한다. 새 파일을 만들지 말고 기존 `/literacy/health`가 있는 파일을 확장한다.

전역 인증 미들웨어 화이트리스트를 **수정하지 마라.** 관리자용이므로 로그인이 걸려 있는 게 맞다.

### 4-2. 화면 구성

```
/literacy/review           — 허브. 세 작업의 진행 현황과 링크
/literacy/review/quiz      — 문항 검수
/literacy/review/definition — 뜻풀이 작성
/literacy/review/level     — 속담·관용구 레벨 부여
```

### 4-3. 공통 규칙

- **한 화면에 한 건.** 목록형이 아니라 한 건씩 넘기는 방식. 248건을 한 페이지에 뿌리면 검수가 안 된다
- **저장 후 자동으로 다음 건으로 이동.** 클릭 수를 최소화한다
- **키보드 단축키를 지원한다.** 손이 마우스를 떠나지 않게. 각 화면의 단축키는 화면 하단에 표시
- 상단에 진행 상황 표시 (`검수완료 34 / 248`)
- **이전 건으로 돌아가기** 가능. 잘못 눌렀을 때 되돌릴 수 있어야 한다
- 필터: 레벨별, 출처별, 카테고리별
- 저장은 `fetch()`로 같은 라우터의 POST 엔드포인트 호출. 페이지 새로고침 없이 처리
- **저장 실패 시 화면에 명확히 표시하라.** 조용히 실패하면 검수한 내용이 통째로 날아간다

### 4-4. 템플릿

`base.html` 상속, `content` 블록 사용. 기존 `/review` 템플릿 구조를 따른다. **기존 템플릿 파일을 수정하지 말고 새로 만든다.**

## 5. 화면 ① 문항 검수 (`/literacy/review/quiz`)

대상: `quiz_items`에서 `review_status='검수전'`

### 표시할 것

- 단어(또는 속담)와 레벨, 출처
- 문제 문장
- 선택지 4개 — **정답을 시각적으로 구분**해서 표시
- 원본 `terms.definition` (정답이 맞는지 대조용)
- `sense_category` (오답이 적절한 범주에서 나왔는지 확인용)

### 조작

- **O (합격)** → `review_status='검수완료'`
- **X (불합격)** → `review_status='제외'`
- **보류** → `review_status='보류'`
- 메모 입력 (`note`)
- 판정 시 `reviewed_at` 기록

단축키: `1`=O, `2`=X, `3`=보류, `←`/`→`=이동

### 중요

**X 판정 시 사유를 선택하게 하라.** 자유 입력만 두면 아무도 안 쓴다.

- 정답이 틀림
- 오답이 너무 쉬움 (소거법으로 풀림)
- 오답이 정답에 가까움 (정답이 둘)
- 표기 문제 (숫자 접미사 등)
- 레벨 부적절
- 기타 (메모 필수)

이 사유 분포가 다음 프롬프트 개선의 근거가 된다. 집계해서 보여주는 화면도 만들어라 (`/literacy/review/quiz/stats`).

## 6. 화면 ② 뜻풀이 작성 (`/literacy/review/definition`)

대상: `terms`에서 `definition`이 비어 있는 행 (약 697건, 대부분 `schemareading-schema`)

### 표시할 것

- 표제어, 레벨, 대/중/소분류
- **같은 소분류의 다른 어휘와 그 뜻풀이 3~5개** — 문체를 맞추기 위한 참고
- 입력란 (뜻풀이)

### 조작

- 뜻풀이 입력 후 저장 → `review_status='검수완료'`, `reviewed_at` 기록
- 건너뛰기 → 다음 건
- 소분류 단위로 필터링. **같은 주제를 연달아 작업하는 게 훨씬 빠르다**

### 하지 말 것

**이번 단계에서 AI 자동 생성 기능을 붙이지 마라.** 화면부터 만들고, 자동 생성은 별도 단계에서 결정한다. 지금 넣으면 검수 UI가 완성되기 전에 697건이 AI 초안으로 채워져 버린다.

## 7. 화면 ③ 레벨 부여 (`/literacy/review/level`)

대상: `terms`에서 `category IN ('속담','관용구')` 이고 `level IS NULL` (2,884건)

전량 처리는 비현실적이다. **표본 작업 화면으로 설계한다.**

### 표시할 것

- 속담/관용구와 뜻풀이
- 레벨 선택 버튼 (0~6, 그리고 "해당 없음")
- 이미 레벨이 매겨진 비슷한 항목이 있으면 참고로 표시

### 조작

- 레벨 클릭 → 저장, `grade_source='manual'`, 다음 건
- 단축키: `0`~`6` 숫자키로 즉시 선택
- 건너뛰기 가능

### 순서

무작위가 아니라 **뜻풀이가 짧고 흔한 것부터** 보여준다. 널리 쓰이는 속담일수록 레벨 판단이 쉽고, 실제 출제 가능성도 높다.

"해당 없음"은 초중고 교육과정에 낼 만하지 않은 항목용이다. `review_status='제외'`로 처리한다.
