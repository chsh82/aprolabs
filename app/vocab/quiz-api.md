# 문항 공급 API 계약

```
GET /quiz?format=<형식>&count=<개수>&level=<학년>&topic=<주제>&exclude=<id,id>
```

공통 응답:

```json
{ "format": "gate3", "items": [ ... ] }
```

모든 item은 `id` 를 갖는다. 학습 기록(`attempt`)이 이 값을 참조한다.

---

## gate3 — 3지선다 (뜻 → 낱말)

`voyage/suez`, `voyage/elephant`, `voyage/furnace`

```json
{
  "id": 1204,
  "mean": "두 육지 사이에 낀 좁은 바닷길",
  "a": "해협",
  "w": ["반도", "삼각주"],
  "why": "도버 해협, 대한 해협처럼 씁니다."
}
```

`w` 는 정확히 2개. 혼동쌍 우선.

---

## mc4 — 4지선다 (문두 + 보기)

`voyage/pacific`, `voyage/train`

```json
{
  "id": 1310,
  "q": "밑줄 친 말의 뜻은?  “하루를 <em>벌었다</em>.”",
  "opts": ["돈을 모았다", "여유를 얻었다", "힘껏 일했다", "길을 잃었다"],
  "a": 1,
  "why": "'벌다'에는 시간이나 여유를 얻는다는 뜻도 있습니다."
}
```

`a` 는 `opts` 의 인덱스. `q` 안의 `<em>` 은 밑줄로 렌더된다. 다른 태그는 넣지 않는다.

pacific 은 `mean` 형태(뜻 제시)도 받으므로 `q` 대신 `mean` + `a` + `w[3]` 로 내려도 된다. 둘 중 하나로 통일할 것.

## assemble — 4글자 조합

`voyage/hongkong`

```json
{
  "id": 880,
  "mean": "눈앞의 차이만 보고 속아 넘어감",
  "word": "조삼모사",
  "why": "아침에 셋 저녁에 넷이나 같은 수입니다."
}
```

함께 내려줄 것:

```json
"distract": ["와", "신", "담", "절", "치", "부", "새", "옹"]
```

`word` 에 포함되지 않은 글자만. 다른 성어의 구성 글자에서 뽑는다.

---

## situation4 — 상황문 + 4지선다

`idiom/archery`

```json
{
  "id": 101,
  "kor": "우공이산",
  "han": "愚公移山",
  "mean": "우직하게 밀고 나가면 결국 큰일을 이룬다.",
  "situation": "매일 겨우 한 쪽씩 읽던 지훈이가 삼 년 만에 백 권을 채웠다.",
  "wrong": ["대기만성", "고진감래", "사면초가"]
}
```

`situation` 은 성어를 직접 언급하지 않는 서술문이어야 한다. 성어가 문장에 들어가면 문제가 성립하지 않는다.

## hanja — 한자 구성

`idiom/snake`, `idiom/runner`, `idiom/nautilus`

```json
{
  "id": 101,
  "kor": "우공이산",
  "han": "愚公移山",
  "mean": "우직하게 밀고 나가면 결국 이룬다"
}
```

함께 내려줄 것:

```json
"hun": { "愚": "어리석을 우", "公": "공평할 공", "移": "옮길 이", "山": "뫼 산" }
```

`hanja` 테이블의 `hun` + `eum` 을 합친 값. 요청한 문항들이 쓰는 글자를 모두 포함해야 한다.

## usage — 오용 판정

`idiom/judge`

```json
{
  "id": 442,
  "idiom": "반포지효",
  "ok": false,
  "s": "부모님이 떠나신 뒤에야 효도하지 못한 것이 한스러워 <em>반포지효</em>의 심정이 되었다.",
  "type": "혼동",
  "why": "이미 부모가 안 계신 뒤의 한탄입니다.",
  "fix": "풍수지탄이 맞습니다. 반포지효는 부모가 계실 때 은혜를 갚는 효도입니다."
}
```

`ok: true` 인 항목은 `type` `why` `fix` 를 비운다.

`type` 은 다음 넷 중 하나로 고정한다. 이 분류가 학생에게 그대로 노출된다.

| type | 뜻 |
|---|---|
| `혼동` | 비슷한 성어와 뒤바뀜 |
| `상황 불일치` | 뜻과 맞지 않는 상황에 씀 |
| `주체 오류` | 주는 쪽과 받는 쪽이 뒤바뀜 |
| `의미 중복` | 성어의 뜻을 뒤에서 반복 |
| `반대로 씀` | 정반대 뜻으로 씀 |

**바르게 쓰인 문장을 절반 넣는다.** 오용만 나오면 학생이 문장을 읽지 않고 전부 "잘못 쓰였다"를 눌러 만점을 받는다.

## 난이도 파라미터

`level` 은 1~12(학년). 서버는 `idiom.level_min` 으로 필터링한다.

`level_min` 은 저장된 값을 그대로 쓰지 말고, 세 축에서 계산할 수 있게 열어 둔다.

```
level_min = f(hanja_score, abstraction_score, frequency_score)
```

세 값을 따로 저장해 둔 이유가 이것이다. 등급 기준이 바뀌면 전수 재검토 없이 계산식만 고친다.
