# 데이터 복원 후보 조사 (2026-09-19, 2차 안정화)

승인 문서 7건 중 선택지·표 열 정의가 없어 QA를 차단하는 문항, 그리고 `ui_type='unknown'`으로
분류된 문항에 대해, `discussion_qa.raw_text`(추출 원문)와 `question_text`만으로 구조를
복원할 수 있는지 조사했다. **운영 DB는 이 조사만으로 수정하지 않았다** — 아래는 검수자가
검수화면에서 반영 여부를 판단할 수 있도록 근거만 정리한 것이다. `ui_config`는 JSON이라
검수화면에 아직 직접 편집 UI가 없다면, 이 표를 참고해 수동으로(또는 별도 스크립트로) 채워
넣기 전에 반드시 사람이 원본 PDF와 대조하길 권한다 — 아래 "신뢰도"가 "높음"인 것도 추출
과정의 줄바꿈 오류 가능성은 남아 있다.

## 상세

### id=835 — L3-Q4-W01 #7 (table_compare) — 복원 가능, 신뢰도 높음

raw_text에 표 구조가 그대로 남아 있다:
```
중국의 나라 이름        고구려와 어떤 일이 있었나요?
수나라 ... (589년 중국을 통일한 뒤 ...)
당나라 ... (618년, 중국을 통일했어요 ...)
```
헤더 2개("중국의 나라 이름", "고구려와 어떤 일이 있었나요?")와 행 2개(수나라/당나라)가
명확히 구분된다.

**복원 후보**:
```json
{"columns": ["중국의 나라 이름", "고구려와 어떤 일이 있었나요?"], "rows": 2}
```
(표는 학생이 직접 채우는 빈 답란이라 셀 내용 자체는 ui_config에 안 들어감 - `bodyTableCompare`가
`rows` 개수만큼 빈 답란 행을 만든다. 열 제목만 있으면 렌더링 가능.)

### id=840 — L3-Q4-W02 #4-1 (table_compare) — 부분 복원, 신뢰도 낮음

raw_text:
```
예전의 한글               달라진 점
장우나
```
헤더 2개("예전의 한글", "달라진 점")는 보이지만, 실제 비교 대상 행이 "장우나" 한 단어만
남고 잘려 있다(OCR/추출 과정에서 잘린 것으로 보임 - 원본 PDF의 표에 몇 개 단어가
있었는지 이 텍스트만으로는 알 수 없음). **열 제목은 복원 가능하지만 행 개수(`rows`)를
추측으로 채우면 원본과 다를 위험이 커서, 이 항목은 원본 PDF 재확인 전에는 복원하지
않는 걸 권한다.**

### id=423 — L5-Q4-W01 #1-1 (table_compare) — 부분 복원, 신뢰도 중간

raw_text:
```
밝은 면
어두운 면
```
헤더 2개는 명확("밝은 면"/"어두운 면")하지만, 구체적 항목 나열이 없어 몇 행이 필요한지
알 수 없다. 2개 범주를 나란히 비교하는 구조로 보아 **1행**(밝은 면 칸/어두운 면 칸에
각각 서술)이 자연스러워 보이지만, 이는 추측이다.

**복원 후보(참고용, 행 수는 추정치)**:
```json
{"columns": ["밝은 면", "어두운 면"], "rows": 1}
```

### id=114 — L5-Q4-W10 #3 (choice_multi) — 복원 불가

`raw_text`가 DB에 `NULL`이다 — 추출 단계에서 이 행에 원문 자체가 저장되지 않았다.
`question_text`만으로는 선택지 문구를 지어내는 것이므로(내용 지어내기 금지), **복원 근거가
없다. 원본 PDF를 다시 봐야 한다** — 이 저장소 안 자료만으로는 해결 불가.

### id=1607, id=1611 — L1-Q4-W01 #1, #5 (unknown) — 재분류 후보, 신뢰도 중간

둘 다 "왜 ~했나요?"/"왜 ~했을까요?" 형태의 개방형 서술 질문이고, raw_text에 선택지나
표 구조의 흔적이 없다 — 애초에 선다형/표형이 아니라 **서술형(text_long)으로 분류돼야
했는데 어떤 유형에도 배정되지 못하고 unknown으로 남은 것**으로 보인다. 다만 `text_short`와
`text_long` 중 어느 쪽이 맞는지, `ui_config.starter`(예시 문장)를 채울지는 원본 PDF의
답란 크기를 봐야 확실하다 - 그래서 신뢰도를 "중간"으로 뒀다.

**재분류 후보**: `ui_type: "text_long"`(질문 난이도·길이로 볼 때 서술형에 더 가까움).

### id=843 — L3-Q4-W02 #5 (unknown) — 재분류 후보, 신뢰도 낮음~중간

raw_text에 편지 원문 전체("그동안 네가 떠다 준 물 잘 마셨다...")가 질문 문구와 섞여
그대로 들어있다. 이건 단순 재분류로 안 끝나고, 편지 부분을 `excerpt_text`로,
"장운이가 받았던 편지를 직접 해석해 봅시다"를 `question_text`로 **나누는 작업이 먼저
필요**하다 - 현재 상태로 `ui_type`만 `text_long`으로 바꾸면 질문 칸에 편지 원문까지
전부 들어가 버린다. 자동 분리는 문장 경계 추정이 필요해 이번 조사 범위에서 확정하지
않았다.

### id=435 — L5-Q4-W02 #4 (unknown) — 재분류 후보, 신뢰도 중간

raw_text 끝에 "언해본에 담긴 / 훈민정음의 / 창제의 이유"라는 짧은 구절이 붙어 있는데,
이게 소제목/힌트인지 답안 예시인지 원문만으로는 판단이 애매하다. 본문(훈민정음 언해본
인용)은 이미 `question_text`에 들어가 있어 excerpt 분리 문제는 없다.

**재분류 후보**: `ui_type: "text_long"`, 끝의 짧은 구절은 `ui_config.starter`(답변 시작
힌트) 후보로 검토 — 다만 원본 PDF에서 이게 정말 힌트 문구인지 먼저 확인 필요.
