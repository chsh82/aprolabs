# 스키마리딩 4단계: 연구용 DB 연결 결정 v5

근거: 사용자가 전달한 `reports/schema_reading_phase3_dryrun_20260924.md`
요약. 보고서 원문과 두 DB는 이 작업 공간에서 직접 볼 수 없으므로,
아래 수치·대상 ID는 Claude Code가 원문과 다시 대조한다.

## 현재 확인된 결과

- 표제어 집합은 148개이고, 출처가 중복된 행을 포함해 **판정 행은 150**:
  `APPROVABLE_CANDIDATE` 142, `MULTIPLE_LINKS` 4(표제어 2개),
  `AMBIGUOUS_SENSE` 2, `UNVERIFIED_DEFINITION` 2.
- `속수무책`, `혼비백산`은 각각 동일 퀴즈 콘텐츠에
  `momo-textbook`과 `사자성어-pdf` 원천 어휘가 동시에 연결된다.
  출처별 레벨도 다르다. 실제 1:N 반례가 있으므로 단일
  `literacy_term_id` 컬럼을 전체 데이터 설계로 확정하지 않는다.
- 옛 정책과 관련된 `literacy.db` 레벨 5는 62건(krdict 25,
  사자성어-pdf 37) + 원본 레벨 5 615건(스키마 507,
  학습도구어 108) = **677건**. 레벨 6의 별도 **693건**도
  학년 정책 재검토 범위다. 서로 겹치지 않는 것으로 보고되었다.
  현재 퀴즈 DB의 L5/L6은 0건이라고 보고되었으며 다시 확인한다.

## 확정하는 처리 규칙

1. **4개 의미 보류 행**(`시샘`, `평론`, `능가하다`, `설상가상`)은
   지금 링크/문항/레벨을 승격하지 않는다. 자동화된 독립 재판정용
   검토 카드에 양쪽 뜻풀이·품사·원천 ID·예문/선택지를 제시하고
   차이의 근거를 기록한다. 의미가 불확실하면 계속 보류한다.
   사용자에게 즉시 수동 검수를 요청해 전체 작업을 멈추지 않는다.
2. **다중 출처 2개 표제어**는 어느 하나의 출처를 버리는 전역
   우선순위를 만들지 않는다. `momo-textbook`과 `사자성어-pdf`를
   각각 관계로 보존하고 레벨을 자동 계승하지 않는다. 퀴즈 표시상
   원천 하나를 골라야 한다면, 어휘 퀴즈에서는 검증된 뜻과 일치하는
   `momo-textbook`을 표시 후보 1순위로만 둔다. 사자성어 기능은
   `사자성어-pdf`를 별도 자료로 사용한다. 둘의 뜻 또는 레벨 정책이
   충돌하면 두 연결 모두 검토 상태로 두며 강제 1:1 링크를 만들지 않는다.
3. **연결 스키마는 관계 테이블**을 기본안으로 한다. 예:
   `vocabulary_content_literacy_links(content_id, literacy_term_id,
   link_status, source, provenance_version, created_at)`.
   `(content_id, literacy_term_id)` UNIQUE, `content_id`는 현행
   퀴즈 콘텐츠 FK, `literacy_term_id`는 다른 SQLite 파일의 키라서
   두 DB를 대조하는 검증 스크립트로 유효성을 관리한다.
   실제 PK 타입/이름·기존 관계 테이블 여부를 확인해 최종 스키마를
   확정한다. 1:N 반례와 V/S 중첩을 잃지 않는 최소 구조다.
4. **142건의 `APPROVABLE_CANDIDATE`**는 연구용 비공개 링크의
   첫 배치가 될 수 있다. 이 수치는 최종 삽입 수가 아니다. 원문
   150행의 ID 중복/뜻/교차 DB 키 유효성 검사를 통과한 건만
   staging에 반영한다. 기존 콘텐츠의 뜻·레벨·문항·공개 플래그는
   변경하지 않는다. `MULTIPLE_LINKS` 4행은 첫 배치에서 보류한다.
5. **레벨 5·6의 1,370건(677+693)은 별도 재평가 큐**로 두고
   이번 링크 배치에서 제외한다. 62건은 옛 AI 정책의 결과이므로
   새 정책에 따라 근거를 재검토한다. 615/693건도 단지 원본
   레벨 숫자만으로 학년을 일괄 확정하지 않는다. 사용자 확정 학년
   정책은 L5=고1, L6=고2~3이다.
6. 해시가 서로 다른 옛 `어휘퀴즈DB.xlsx` 두 버전과 해당 338문항은
   이번 연결 배치 범위에서 제외한다. 정본/차이 검사는 후속 작업이다.

## 연구용 적용 순서와 통과 기준

Claude Code는 보고서 원문, 실제 모델, 9개 게이트를 확인하고
**migration 및 import 스크립트의 dry-run/rollback 경로를 먼저 구현**한다.
연구용 적용은 SQLite Backup API 백업과 복원 가능성을 검증한 후,
142개 후보 가운데 모든 검사를 통과한 비공개 관계만 단일 트랜잭션으로
추가한다. 연구용 환경이 아니면 적용 중지. 두 DB 교차 참조 무결성,
`PRAGMA integrity_check`, `foreign_key_check`, 재실행 멱등성,
기존 5,723개 콘텐츠/문항의 불변성, 노출/공개 합계 0을 재확인한다.
검증 실패 시 트랜잭션 롤백·백업 복원 절차를 보고한다. 앱 라우터가
새 링크를 아직 읽지 않더라도 이번 단계의 목적은 관계 검증이다.
