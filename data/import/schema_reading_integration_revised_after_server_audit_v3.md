# 스키마리딩·어휘 퀴즈 통합 계획 v3: 서버 조사 결과 반영

기준: 2026-09-23, Claude Code가 사용자에게 보고한 로컬·연구용 서버
읽기 전용 조사 요약. 보고서 원문 `reports/schema_reading_phase1_baseline_20260923.md`와
서버 코드는 이 작업 공간에 없으므로 상세 컬럼/코드 판단은 추후 원문 확인이
필요하다. 이 문서는 실제 스키마 변경 승인이나 적용 지시가 아니다.

## 확정한 입력과 정책

- `internal_vocab_upper_restore_v1.zip`은 이 작업에서 만든 **상위 단계 원천
  감사 패키지**다. momo-textbook 821건이나 krdict 2,884건이 아니다.
  스키마·학습도구어 XLSX 2개, 상위 출현 2,320행, 의미 감사 822행,
  학생용 비공개 뜻풀이·예문 초안 73건이 포함되어 있다.
- `스키마리딩 참고자료.zip`은 사용자 제공 자료이며 학습 흐름, 전체 XLSX,
  옛 퀴즈 338행 등을 포함한다. 실제 FastAPI 프로젝트에 옮길 때는 두 ZIP의
  SHA-256과 파일별 원본을 확인한다.
- **사용자가 재확정한 서비스 학년 정책:** L0=초1~2, L1=초3~4,
  L2=초5~6, L3=중1~2, L4=중3, L5=고1, L6=고2~3.
  서버의 기존 `GRADE_LABELS`와 `app/literacy` 문서가 이와 다른 점은
  버전 불일치이며, 사용자 정책이 우선한다. 코드 라벨만 변경하기 전에
  기존 콘텐츠 레벨 배정이 과거 학년 범위를 사용했는지 조사한다.

## 새로 확인된 실제 구조

- 연구용 서버는 `APP_ENV=research`와 연구용 `VOCABULARY_QUIZ_DB_PATH`를
  사용하며 SQLite 무결성 및 FK 검사를 통과했다고 보고되었다.
- 기존 `app/literacy`가 별도 `data/literacy.db`에 학습도구어 **1,321건**과
  스키마어휘 **2,061건**을 이미 갖고 있다. 이 모듈의 `source`로 V/S를
  구분할 수 있다고 보고되었다. `vocabulary_quiz_research.db`의 현행
  5,723건과는 아직 데이터 연결이 없다.
- 업로드된 원본 엑셀의 보이는 표제어 행(학습도구어 2,035,
  스키마 2,252)은 `literacy.db` 적재 건수와 다르다. 대상 학년, 중복,
  이전 검증·제외 정책의 차이를 조사해야 하며 단순 결손으로 단정하지 않는다.
- `vocabulary_content_levels` 실제 컬럼 `vocab_level`·`level_status`를
  기준선 도구 초판이 집계하지 못했다. 점검 도구를 고쳐 다시 확인한다.

## 수정된 통합 구조

| 역할 | 현행 자산 | 다음 판단 |
|---|---|---|
| 학습도구어·교과 개념어의 원천 | `app/literacy` 및 `literacy.db` | 원본 XLSX/감사 패키지와 출처·주차·뜻·레벨을 행별 대조. 누락된 관계만 보완 |
| 학생용 뜻·예문·퀴즈 | `vocabulary_quiz_research.db`의 기존 콘텐츠·문항·레벨 | 5,723개 기존 콘텐츠와 뜻 단위로 대조하고 확인된 경우에만 연결 |
| 주차·교과·주제 | `app/literacy`의 현행 관계 구조 | 실제 스키마가 충분하면 재사용. 부족할 때에만 관계 확장 |
| 두 모듈 간 연결 | 아직 없음 | 매칭의 기수성과 안정적인 ID를 검사한 후 연결 구조 선택 |

**1:1 관계가 확인되면** `vocabulary_contents.literacy_term_id` 같은 nullable
컬럼 하나가 최소 변경일 수 있다. **1:N 또는 N:M, 다의어, V/S 겹침이
있으면** `content_id`·`literacy_term_id`·원천 의미·연결 상태를 가진
별도 관계 테이블이 필요하다. 서로 다른 SQLite 파일 간에는 DB 수준의
일반 FK를 걸 수 없으므로, 두 파일의 식별자 존재 여부를 앱 로직과
검증 스크립트에서 재확인한다. 어느 방식을 택할지는 실데이터의
중복/기수성 확인 결과로 결정한다.

## 다음 실행 단계

1. **보고서 원문·스키마 조사:** `reports/schema_reading_phase1_baseline_20260923.md`와
   `app/literacy` 모델, `literacy.db` 테이블·필드·기존 수입 기록을 읽는다.
   데이터 수정 없이 연구용/로컬 두 DB의 실제 상태를 대조한다.
2. **원본 재현 대조:** 두 ZIP을 로컬 `data/import/`에 놓고 원본 파일의
   체크섬을 확인한다. 현재 `literacy.db` 1,321+2,061건과 원본 행을
   일대일/중복/제외/의미 불일치로 분류한다. `source` V/S와 주차·주제
   관계가 정말 있는지 확인한다. 누락이 있으면 작은 배치로 보완할 기준을
   제안한다.
3. **기존 5,723건과의 연결 분석:** 이름 일치뿐 아니라 품사·원천 뜻·
   현행 의미를 비교하고 매칭 가능한 `literacy` ID의 기수성을 집계한다.
   상위 822행의 과거 의미 후보 334건과 73건 학생용 초안을 우선 검증하되,
   현행 연결 성공 수는 새로 계산한다.
4. **학년 정책 충돌 분석:** `GRADE_LABELS`, `literacy` 레벨 정의,
   `vocabulary_content_levels` 레벨 배정 근거를 조사한다. L5/L6의
   현재 행 수, 원래 학년 또는 원천 단계, 영향을 받는 출제 코드를 보고한다.
   검증 없이 라벨만 교체하거나 L5/L6 기존 행을 일괄 재배정하지 않는다.
5. **연결 방식 결정·dry-run:** 실제 기수성에 따라 nullable FK 또는
   관계 테이블 중 최소 구조를 선택한다. 원천 재적재가 필요한 경우에만
   `literacy.db` 쪽 dry-run을 별도로 만든다. 두 DB 백업·FK 대체 검증·
   기존 콘텐츠 해시·멱등성·학생 공개 0을 통과한 뒤 연구용 적용을 준비한다.
6. **콘텐츠·출제 확대:** 73건 비공개 초안 중 현행 의미가 확인된 건부터
   관리자 전용 출제; 이어서 L4/L5 나머지 194건, L6 의미 후보 67건,
   스키마 주제별 개념 보완. 옛 퀴즈 338행은 별도 선택지 검증 후 활용한다.

다음 요청의 산출물은 ① 실제 `literacy.db` 대 원본의 행별 대조 보고,
② 두 DB의 매칭 기수성 표, ③ L5/L6 영향 목록, ④ 연결 방식 선택 근거,
⑤ 이후 dry-run 명세다. 조사 단계에서는 어느 DB도 변경하지 않는다.
