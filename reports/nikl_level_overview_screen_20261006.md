## 3. 현재 레벨 vs 변경안 기준 출제량 비교

**산출**: `scripts/vocab/build_level_volume_impact.py`,
`data/import/nikl_level_volume_impact_20261006.csv`.

실제 선택 함수(`_matching_level_content_ids`/`_select_level_candidates`,
`app/vocabulary_quiz/routers/multiformat.py`)와 **완전히 동일한 규칙**으로
재현했다: `source_version='2.1.29'`(1,289건)만 포함, `CROSSWORD`는 레벨
모드에서 항상 제외(100건, 전체 모드 전용이라 이번 변경과 무관),
`MATCH_WORD_MEANING`은 연결된 content_id 전부가 같은 레벨일 때만 포함(대표/
평균 레벨 생성 안 함), `confidence_mode`(all_candidates/auto_only) 두
모드 전부 계산. "변경안"은 레벨 숫자가 실제로 바뀌는 두 범주(RULE_A/B,
tier1_기본레벨조정, 합계 1,416건)만 가정 적용했다 - level_status/
boundary_flag는 dry-run이 건드리지 않으므로 시뮬레이션에서도 그대로 뒀다.

| 모드 | 레벨 | 현재 문항수 | 변경안 문항수 | Δ | 현재 고유어휘 | 변경안 고유어휘 | Δ |
|---|---|---:|---:|---:|---:|---:|---:|
| all_candidates | L2(초5~6) | 332 | 617 | **+285** | 88 | 164 | **+76** |
| all_candidates | L3(중1~2) | 338 | 42 | **-296** | 91 | 11 | **-80** |
| all_candidates | L1(초3~4) | 316 | 332 | +16 | 87 | 91 | +4 |
| all_candidates | L0/L4/L5/L6 | 변화 없음 | | | | | |
| auto_only | L2(초5~6) | 4 | 289 | **+285** | 1 | 78 | **+77** |
| auto_only | L3(중1~2) | 316 | 31 | **-285** | 85 | 8 | **-77** |
| auto_only | L0/L1/L4/L5/L6 | 변화 없음 | | | | | |

**해석**: RULE_A(1,368건, 공식4등급∧현재L3→L2)가 이 변화의 거의 전부를
차지한다 - 실제로 적용하면 **중등 1~2학년(L3) 문항 풀이 현재의 10~12%
수준으로 급감**하고(auto_only 기준 316→31건, 85→8 고유어휘) 초등 5~6학년
(L2) 풀이 그만큼 불어난다. 이건 "RULE_A를 실제로 적용해도 되는가"를
판단할 때 반드시 봐야 할 수치라서, 적용 여부 판단 전에 먼저 남겨둔다(적용은
이번에도 하지 않았다).

**기존 파일럿·L0~L3 미리보기 영향(별도 표시)**:

| 풀 | 매니페스트 content_id | 변경 대상과 겹침 |
|---|---:|---:|
| L4/L5 파일럿(phase18, 40문항) | 20종 | **0건** |
| L6 파일럿(phase28, 40문항) | 20종 | **0건** |
| 기존 코퍼스 L0~L3 확장 미리보기(184문항) | 92종 | **20건** |

파일럿 두 개는 전혀 다른 `source_version`을 쓰는 완전히 별도 문항 풀이라
레벨이 바뀌어도 그 풀 자체에는 영향이 없다(영향 0건으로 확인됐을 뿐, 애초에
구조적으로 격리돼 있음). **L0~L3 확장 미리보기는 20건이 영향권**이다 -
매니페스트의 고정 92개 content_id 중 20개가 RULE_A/B 대상이라, 그 20개의
"레벨 미확정(PROVISIONAL_AUTO)" 표시 버킷이(예: L3 미리보기에서 L2
미리보기로) 바뀔 수 있다 - 문항이 풀에서 빠지는 건 아니고 어느 레벨 아래
보이느냐가 바뀐다는 뜻이다.

## 4. 경계 처리 설계 — 학생 공개 게이트 vs 관리자 연구용 출제

**확인된 사실(추측 아님, 코드·데이터로 확인)**:

1. **두 메커니즘은 이미 코드 수준에서 완전히 분리돼 있다.**
   `VocabularyContentLevel` 모델 docstring 그대로: *"아직 학생 출제/공개
   (student_exposure, public_ready)에는 전혀 연결되지 않은 '자동 후보'
   단계"*. `vocabulary_quiz` 안에서 `public_ready`를 실제로 읽어 서빙을
   결정하는 코드는 **없다**(L6 파일럿 쪽에 "여전히 0인지" 확인하는 안전
   어서션이 하나 있을 뿐, 그 값으로 뭔가를 보여주거나 막는 코드가 아니다) -
   `public_ready`를 실제로 1로 바꾸는 라우트/버튼도 이 코드베이스 어디에도
   없다(`publish_review.py` 자체가 "절대 하지 않는 것: ... 실제 승격(공개
   전환) 버튼이나 API"라고 명시). 즉 **학생 공개 게이트는 아직 미구현
   상태**이고, 그래서 지금 이 순간 "`public_ready=0`이 관리자 출제를
   막는다"는 문제 자체가 존재하지 않는다 - 지시한 "일괄 차단하지 마라"는
   조건이 이미 충족돼 있다(새로 코드를 고칠 필요 없음).
2. **`confidence_mode`가 이미 "관리자 연구용 출제" 안에서의 경계 처리
   레버다.** `_matching_level_content_ids()`는 `level_status`를 직접
   필터한다 - `all_candidates`(PROVISIONAL_AUTO+REVIEW_BOUNDARY, 경계
   포함) vs `auto_only`(PROVISIONAL_AUTO만, 경계 제외) 두 모드를 호출자가
   선택한다(관리자 화면에 "전체 후보/고신뢰도만" 토글로 이미 노출돼 있음).
   **정정**: 지난 보고서(`nikl_level_policy_finalization_20261006.md` 5절)
   에서 "`_select_level_candidates()`가 `boundary_flag`/`level_status`를
   전혀 보지 않는다"고 썼는데, 이번에 함수 본문을 직접 다시 읽어 **이
   서술이 틀렸음을 확인했다** - 실제로는 `confidence_mode`를 통해 본다.
   이 정정을 이 보고서에 남긴다.
3. **공식 추천 범위("경계(L3~L4)")와 기존 `level_status='REVIEW_BOUNDARY'`
   는 서로 다른 것이다.** 라이브 데이터로 직접 대조한 결과: 공식5등급
   매칭 49건은 **전부** `level_status='REVIEW_BOUNDARY'`(`boundary_flag=1`)
   이지만, 전체 `REVIEW_BOUNDARY` 건수는 **2,370건**이다 - 나머지
   **2,321건**은 이 NIKL 공식등급 작업과 전혀 무관한 다른 이유로 경계
   표시가 돼 있다(레벨 정책 전반에서 범용으로 쓰는 플래그). 둘을 같은
   의미로 섞어 쓰면 "경계=전부 공식5등급" 같은 잘못된 추론을 하게 된다 -
   화면(2절)에서도 두 필드를 별도 컬럼으로 뚜렷이 분리해 뒀다.

**제안(신규 미검수 경계 후보 — 16,800건 — 를 위한 것, 이번엔 코드 변경
없음)**:
- 장래에 이 16,800건 중 일부를 실제 `vocabulary_contents`로 들여올 때는
  `vocab_level`에 L3/L4 중 하나를 임의로 배정하지 않고, **기존 메커니즘
  그대로** `level_status='REVIEW_BOUNDARY'`로 적재한다 - 그러면 `auto_only`
  모드(관리자가 "고신뢰도만" 선택) 출제에서는 자동으로 빠지고,
  `all_candidates` 모드(관리자가 명시적으로 "전체 후보" 선택)에서는 연구
  목적으로 여전히 볼 수 있다 - 새 코드 없이 기존 레버 하나로 지시한 두
  요구("임의로 단일 레벨에 넣지 않음" + "관리자 연구용 출제를 일괄 차단하지
  않음")를 동시에 만족한다.
- `public_ready`/`student_exposure`는 이 신규 건들에도 계속 기본값 0으로
  둔다(학생 공개 게이트가 실제로 구현되는 시점까지는 어차피 무관하다).
