# 중등 어휘 레벨 검수 1차 배치(100건) 후속 분석 + 최소정보 분류기 초안 (읽기 전용)

- 일자: 2026-10-02
- 범위: 1차 배치 100건의 실제 사람 판정을 조회·분석하고, 최소정보
  분류기 초안을 설계·검증하고, 2차 배치 후보(최대 100건)를 파일로만
  준비한다. **DB 쓰기 전혀 없음**(judgments/batch 테이블 전부 SELECT만
  수행) — `vocab_level`·문항·매니페스트·공개 플래그 변경 없음, 뜻풀이·
  예문·문항 신규 생성 없음, momolib 무관. **완료된 검수 화면·배포는
  이번에 전혀 손대거나 재검증하지 않았다**(이미 완료된 별도 작업).
- 산출 스크립트: `scripts/vocab/nikl_grade5_batch1_analysis.py`

## 1. 배치 100건 최신 판정 조회 + 정합성 검사

라이브 DB(`vocabulary_grade5_candidate_judgments`)를 다시 읽기 전용으로
조회했다(기존 "검수 완료"라는 말을 그대로 믿지 않고 재확인):

| 검사 | 결과 |
|---|---:|
| 배치 100건 중 판정 없음 | **0건** |
| L3 | **60건** |
| L4 | **40건** |
| 경계 유지 | **0건** |
| 제외 | **0건** |
| 중복 판정(같은 candidate_id에 2개 이상 이력) | **0건**(전부 1회만 판정) |
| stale(원천 배치 행이 판정 이후 바뀜) | **0건**(배치 재적재 안 됐으므로 당연한 결과, 앱의 `_batch_version_snapshot()` 해시를 독립 재계산해 실측 확인) |
| 자유서술 근거(rationale) 입력 | **0/100건** |
| 배치 내 표제어 중복 | **0건**(100건 전부 서로 다른 lemma) |

L3/L4 외의 값은 이번 배치에 한 건도 없다 — 2~4절의 "경계 유지"/
"제외" 관련 설계는 전부 **앞으로 발생할 경우를 대비한 것**이며, 이번
100건 분석에서 실제로 다루는 범주는 아니다.

## 2. 품사·전문어·다의어 위험별 판정 분포

**자유서술 근거가 0/100건이므로, 아래 패턴 서술은 전부 이번 분석이
데이터에서 통계적으로 관찰한 것이지 사람이 직접 쓴 이유가 아니다
(명시적으로 "분석자 추론"이라고 표시한다).**

| 품사 | L3 | L4 |
|---|---:|---:|
| 명사 | 38 | 28 |
| 동사 | 9 | 4 |
| 형용사 | 5 | 1 |
| 부사 | 2 | 2 |
| 기타(감탄사/관형사/대명사/수사/의존명사/복합품사 등) | 6 | 5 |

| 전문어 분야(specialized_domain_flag) | L3 | L4 | L3 비율 |
|---|---:|---:|---:|
| 0(일반어) | 45 | 24 | 65% |
| 1(전문어) | 15 | 16 | 48% |

| 다의어 위험(polysemy_risk_flag) | L3 | L4 | L3 비율 |
|---|---:|---:|---:|
| 0 | 57 | 34 | 63% |
| 1 | 3 | 6 | 33%(표본 9건뿐 - 불안정) |

| 고유명사 위험(proper_noun_risk_flag) | 전부 0 | 비고 |
|---|---:|---|
| 1절·전주 보고서에서 이미 확인된 대로 이 자료 자체에 고유명사 신호가 없어 이번 배치에도 전부 0 | - | 판정 분포 분석 불가 |

**분석자 추론(사람이 직접 쓴 이유 아님)**: 전문어 분야 항목은 L3
비율이 65%→48%로 낮아지는 경향이, 다의어 위험 항목은 63%→33%로
더 크게 낮아지는 경향이 관찰된다 — "의미가 복잡하거나 전문적일수록
더 상위 학년(L4)으로 보는 경향"이라는 가설과 방향은 일치하지만,
표본 크기(전문어 31건, 다의어 9건)가 작아 통계적으로 확정할 수
없다.

**뜻풀이 길이 — 가장 뚜렷한 신호(분석자 발견, 사람이 지목한 피처
아님)**: 공식 자료 원문 뜻풀이(`official_meaning_short`)의 문자 수
평균이 L3=39.7자, L4=56.65자로 뚜렷한 차이를 보였다. 이것이 3~4절
분류기 설계의 핵심 피처가 된 배경이다.

## 3. 최소정보 분류기 초안

**입력 피처(사용자 지시대로 5개로 제한)**: 표제어, 품사, 공식등급,
짧은 원문 뜻풀이, 전문어 분야.

- **표제어(lemma) 자체는 식별자라 일반화 피처로 못 쓴다** — 100건
  모두 서로 다른 단어라 "이 글자가 나오면 L4" 같은 규칙은 새 단어에
  전혀 일반화되지 않는다. 입력 목록에는 포함돼 있지만 실제 분류
  규칙에는 쓰지 않았다(투명성 기록).
- **공식등급은 이 배치 전체가 '5' 상수**라 식별력이 0이다 - 역시
  입력엔 있지만 규칙에선 무의미함을 명시한다.
- 실질적으로 쓴 피처는 **뜻풀이 길이(문자 수)**와 **전문어 플래그
  (+5자 상당 가중)** 둘뿐이다 — 2절에서 가장 뚜렷했던 신호다.
- 품사는 사용자가 허용한 입력에 포함되지만, 범주 수가 13개인데
  표본이 100건뿐이라 품사별 세부 규칙을 걸면 즉시 과적합되므로
  **이번 초안에는 넣지 않았다**(과적합 위험을 이유로 뺀 것 - 성능
  때문이 아니라 사전 설계 판단).

**모델링 방식 선택 이유**: sklearn이 이 환경에 설치돼 있지 않고(확인
함), 표본이 100건뿐이라 로지스틱 회귀 이상의 모델은 과적합 위험이
크다고 판단해 **해석 가능한 단일 임계값 규칙**(뜻풀이 길이 임계값
초과 시 L4, 미만 시 L3, 임계값 근방이면 저신뢰로 "경계 유지")을
순수 Python으로 직접 구현했다 - 복잡한 모델을 쓸 재료도 이유도
없다는 것이 설계 판단이다.

**출력 4종**:
- `L3`/`L4` - 임계값 기준 이상 신뢰 구간
- `경계 유지` - 임계값 근방(±8%) 저신뢰 구간 자동 출력(이번 100건
  학습 데이터엔 실제 '경계 유지' 사례가 0건이었지만, 분류기 자체는
  저신뢰일 때 이 값을 낼 수 있게 설계했다)
- `검토 필요` - 이번 초안에서는 실제로 쓰이지 않음(향후 품사 등
  추가 신호가 더 쌓이면 "이 조합은 표본이 아예 없음" 같은 경우에
  쓰도록 예약)
- **'제외'는 분류기 출력에 전혀 포함하지 않는다** - 레벨 판단과
  완전히 다른 축(이 단어를 이번 확장에 넣을지 말지)이라 레벨
  분류기가 건드리지 않는다. 사람이 '제외'로 판정한 항목은 레벨
  예측 대상에서 아예 제외돼야 한다(이번 100건엔 '제외' 사례가 없어
  실제로 테스트하지는 못했다).

## 4. 검증 — 5-fold 교차검증(lemma 그룹 분리 불필요 확인), 다수결 비교

**lemma 그룹 분리 검토**: 100건 전부 서로 다른 표제어라(2절 확인)
같은 단어가 학습/검증 양쪽에 나뉘는 상황 자체가 **구조적으로 발생할
수 없다** — 그룹 분리 제약은 이번 표본에서는 실질적으로 무의미하지만,
점검 자체는 생략하지 않고 코드로 직접 확인했다(향후 배치가 쌓여
같은 단어의 다른 동형이의가 여러 배치에 걸치면 이 점검이 다시
의미를 가진다).

**방법**: 100건을 시드 20261002로 무작위 5등분, 매 fold마다 나머지
80건으로 임계값을 다시 적합(fit)해 20건을 예측 - **검증에 쓰인
항목이 그 fold의 임계값 산정에는 전혀 쓰이지 않았다**(사용자 지시대로
"학습·규칙 설계에 사용한 항목으로 성능을 부풀리지 않음").

| 지표 | 값 |
|---|---:|
| 다수결 베이스라인(전부 L3 예측) 정확도 | **60.0%**(60/100) |
| 분류기 강제예측(L3/L4만, 경계유지 4건 제외) 정확도 | **58.3%**(56/96) |
| 경계유지로 저신뢰 처리된 건수 | 4/100 |
| fold별 적합된 임계값 | fold0=134, fold1=127, fold2=127, fold3=127, **fold4=32** |

**핵심 결론: 이 분류기는 다수결보다도 나쁘다(58.3% < 60.0%).**
fold4에서 임계값이 32로 다른 fold(127~134)와 크게 다르게 적합된 것도
표본이 80건만으로는 임계값 추정 자체가 불안정하다는 뜻이다 -
"뜻풀이 길이가 길수록 L4"라는 2절의 평균값 차이는 실재하지만, 그
신호만으로 새 단어를 안정적으로 분류하기엔 표본이 턱없이 부족하다.

**오분류 사례(실제 fold4 검증에서, 체리픽 아님)**:

| 표제어 | 품사 | 실제 판정 | 예측 | 비고 |
|---|---|---|---|---|
| 멍군 | 명사/감탄사 | L3 | L4(신뢰도 0.95) | 뜻풀이가 길어서 L4로 예측했지만 실제론 L3 |
| 면회하다 | 동사 | L3 | L4(0.766) | 동일 패턴 |
| 유효하다 | 형용사 | L3 | L4(0.875) | 동일 패턴 |
| 원생 | 명사 | L3 | L4(0.95) | 동일 패턴 |
| 자책감 | 명사 | L3 | L4(0.578) | 저신뢰 쪽으로 간신히 L4, 실제론 L3 |

5건 전부 "뜻풀이가 길어서 L4로 예측했는데 사람은 L3로 판정"한
같은 방향의 오류다 - 뜻풀이 길이가 단독 신호로는 체계적으로 과대
적합(overfit to length)돼 있다는 뜻이다.

**결론 및 권고(사용자 지시대로 - 자료 부족 시 자동 확정 대신 검토
대상으로)**: 이 분류기는 **다수결보다 못한 성능이라 어떤 형태로도
자동 확정에 쓰면 안 된다.** 2차 배치(5절)에는 참고용 "제안" 컬럼으로만
붙이고, **화면에 노출하는 것도 권장하지 않는다**(5절 결론 참고) -
n=100, 피처 2개로는 신뢰 구간을 논하기도 어려운 수준이다.

## 5. 2차 배치 후보(최대 100건, 파일로만, 사람 판정 공란)

`data/import/nikl_grade5_crossref_20261001.csv`의 "신규_어휘_후보"
(16,938건)에서 1차 배치 100건의 (표제어,품사,동형번호) 조합을 제외한
뒤, 1차와 동일한 방법(품사×전문어 분야 층화, 비례배분, 고정 시드)으로
**100건**을 뽑았다. 시드는 `20261002`(날짜 기반, 1차의 `20261001`과
구분되는 새 값 - 재실행하면 같은 100건이 재현된다).

각 행에 3절 분류기의 제안을 별도 컬럼(`자동_제안_레벨`,
`자동_제안_신뢰도`)으로 붙였다 - **`사람_판정` 컬럼은 의도적으로
전부 공란**이다(어떤 값도 미리 채우지 않았다). 새 DB 테이블·라우트·
템플릿은 전혀 만들지 않았다 - 순수 CSV 2종(후보 목록 + 분류기 검증
결과)뿐이다.

**"다음 화면에서 제안을 보여줄지" 권고**: **아직은 보여주지 않는
것을 권고한다.** 4절 검증에서 분류기가 다수결보다도 낮은 정확도를
보였으므로, 화면에 "자동 제안: L4(신뢰도 88%)" 같은 표시를 붙이면
오히려 사람 판정에 **그릇된 선입견(anchoring)**을 심어줄 위험이 더
크다. 1~2차 배치가 더 쌓여 표본이 커지고(특히 '경계 유지'/'제외'
실제 사례가 확보되고) 품사 등 추가 피처를 안전하게 쓸 수 있을
만큼 데이터가 모이기 전까지는, 화면은 지금처럼 **빈 판정만** 받는
것이 안전하다.

## 결론 요약 — 사용자가 추가로 확인해야 할 항목

1. **분류기가 다수결보다 성능이 낮다**(58.3% < 60.0%) - 현재 상태로는
   자동 확정은 물론 화면 노출도 권장하지 않는다. 표본이 더 쌓이기
   전까지는 사람이 전부 직접 판정하는 현재 방식 유지를 권고한다.
2. 2차 배치 100건(`nikl_grade5_batch2_candidates_20261002.csv`)이
   파일로 준비됐다 - 이걸 실제 화면에 적재할지(기존 배치 등록
   스크립트 재사용)는 사용자 결정 사항이며, 이번 턴에서는 적재하지
   않았다.
3. 1차 배치 100건은 L3/L4로만 판정됐고 '경계 유지'/'제외' 실례가
   없어, 그 두 출력 경로는 아직 실측 검증이 안 됐다 - 향후 배치에서
   그런 판정이 나오면 재검토 필요.
