대상(38건 item_id)과 근거(위 표)를 이 보고서로 확정해 두고, 실행

## 3. 관리자 정상 출제 경로 확인

일반(혼합 모드) 출제 함수 `_select_question_items()`와 레벨별 출제
함수 `_select_level_candidates()` 둘 다
`VocabularyMultiformatItem.source_version == SOURCE_VERSION`
(하드코딩된 `"2.1.29"`)로 필터링한다(`app/vocabulary_quiz/routers/
multiformat.py`). 이번 배치의 `source_version`은
`"schema_reading_existing_l0l3_dryrun_v1"`이므로 **일반 출제
경로에서는 구조적으로 절대 선택되지 않는다** — 기존 L4·L5 파일럿
(`PILOT_SOURCE_VERSION`)·L6 파일럿(`L6_PILOT_SOURCE_VERSION`)과
동일한, 이미 이 코드베이스에 있는 "배치별 완전 격리" 설계 그대로다.

**DB의 source_version 값을 바꿔 일반 로테이션에 섞지 않았다**(요청대로).

**현재 격리 방식**: 세 번째 독립 배치가 하나 늘어난 상태이며,
`PILOT_SOURCE_VERSION`/`L6_PILOT_SOURCE_VERSION`처럼 자체 전용
UI 토글(`pilot_mode`/`l6_pilot_mode`)이나 URL 파라미터는 **아직
없다**. `/vocabulary-quiz/review?version=...` 화면도 확인했으나 이는
별도 테이블(`VocabularyReviewSample`)을 보는 표본 검수 화면이라 이
배치와 무관(0건으로 표시됨).

**관리자 확인 방법(현재 유일한 방법)**: 운영 서버 프로세스를 건드리지
않는 별도 스크립트에서 `multiformat` 모듈을 불러와 그 스크립트 자신의
import 안에서만 `SOURCE_VERSION`을 이번 배치 값으로 바꾼 뒤, 실제
프로덕션 함수(`_level_availability`/`_select_level_candidates`/
`_grade` 등)를 그대로 호출하는 방식 — 지난 턴에 실제로 수행했고
172/172 PASS 확인함(`vocab_quiz_existing_l0l3_rnd_verification_
20260929.md` 5절 참고). **전용 관리자 UI가 필요하면 별도 개발
과제**(이번 범위 아님).

## 4. L2 17어휘 — 내용 검사와 레벨 확정의 분리 원칙(328건에도 동일 적용)

- L2 17어휘(이미 적재된 142건 중 L2 5어휘 10건 + 신규 통과분 포함)는
  전부 `level_status=PROVISIONAL_AUTO`, `boundary_flag=0`,
  `level_source=NIKL_GRADE_PLUS_DETERMINISTIC_RULES`,
  `level_version=level_policy_v0.1`, `level_confidence=0.664~0.752`
  — **근거 없이 레벨 상태를 바꾸지 않았고(이번 턴 DB 쓰기 0건),
  학생 공개 대상 수로 계산하지도 않았다**(전부 `student_exposure=0`,
  `public_ready=0`로 유지, 이 보고서 어디에도 "공개 가능 수"로
  합산하지 않음).
- **328건에도 동일 원칙 적용**: 1절 표의 "레벨 확정 상태" 칼럼이
  바로 그것 — 328건 전부 이미 레벨 확정(`PROVISIONAL_AUTO`)
  상태였고, 이번 감사도 그 상태를 그대로 읽기만 했다(변경 없음).
  내용 PASS(284건)와 레벨 확정 여부는 표에서 항상 별개 칼럼으로
  분리해 제시했다.
