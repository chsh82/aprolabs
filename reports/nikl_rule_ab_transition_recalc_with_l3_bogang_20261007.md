# RULE_A/B 전환안 재계산 + L3 보강 반영 (읽기 전용, 계산·실행안만)

- 일자: 2026-10-07
- 범위: (1) L3 보강 1·2차 집계 재확인(개별승인 vs 미검수 구분), (2) 일반
  출제 풀과 격리 보강 배치를 분리해 "현재" vs "RULE_A/B 적용 후" 출제량
  비교, (3) 보강 배치를 레벨별 출제에 연결했을 때의 추가량 계산, (4)
  RULE_A/B + L0~L3 매니페스트 + 보강 배치 연결을 묶은 실행안.
- **이번 턴은 계산과 문서 작성까지만** - DB의 레벨·문항·매니페스트·공개
  플래그·momolib 코드는 전혀 바꾸지 않았다(SELECT만 실행, API 호출 0건).
  완료된 L3 검수·배포·분류기 실험은 반복하지 않았다.

## 1. L3 보강 1·2차 집계(개별 승인 vs 미검수/배치 검토 구분)

| 구분 | 콘텐츠 | 문항 |
|---|---:|---:|
| 1차(전수 사람 검수) | 29 | 58 |
| 2차 - 개별 사람 승인(`APPROVED_CANDIDATE`, 신선) | 35 | 70 |
| 2차 - 미검수(수시·숙련·순서도, 승인 추정 안 함) | 3 | 6 |
| **1차+2차 합계** | **67** | **134** |
| 그중 **개별 승인 확정** | **64** | **128** |

미검수 3건은 결함·보류로 재분류하지 않았고, 추가 검수를 이번 작업의
필수 조건으로 요구하지도 않았다 - "검수 전" 상태 그대로 둔 채 아래
계산에서는 **개별 승인 64건·128문항만** "연결 가능한 확정량"으로
쓴다(미검수 3건은 향후 승인되면 그대로 가산되는 여분으로 별도 표기).

## 2. 현재 출제 vs RULE_A/B 적용 후 (일반 풀, 보강 배치와 분리 집계)

**중요 - 집계 분리 원칙**: 아래 수치는 전부 일반 출제 풀
(`source_version='2.1.29'`, `vocabulary_content_levels.level_version=
'level_policy_v0.1'`)만의 것이다. L3 보강 1·2차(67건·134문항)는
**완전히 격리된 별도 source_version**이라 이 "현재 출제" 수치에
**전혀 포함돼 있지 않다** - 134문항이 이미 일반 출제에 들어있는 것처럼
합산하지 않는다.

**핵심 발견 - "레벨행 수"와 "실제 출제 가능 문항 보유 어휘 수"의 큰 괴리**:
`vocabulary_content_levels`에 레벨이 매겨진 어휘는 대부분 아직 실제
문항(`vocabulary_multiformat_items`)이 만들어지지 않은 상태다. 즉 레벨
분류(자동/규칙 기반)는 5,950건 전체에 걸쳐 있지만, 실제로 퀴즈로 낼 수
있는 문항은 그중 소수에만 있다.

### 2-2. RULE_A/B 제안 내용 (PENDING 1,408건)

| 제안 방향 | 건수 |
|---|---:|
| 현재 L3 → 제안 L2(하향) | 1,368 |
| 현재 L2 → 제안 L1(하향) | 40 |
| L3로 신규 편입 제안 | **0** |

**주의(실행안에 직결)**: 1,408건 중 **개별 사람 판정이 이미 끝난 것은
31건뿐**이다(`기본 레벨 조정` 승인 8건 - 이미 적용 완료, `현재 유지`
(제안 거부) 24건). **나머지 1,377건은 아직 아무도 개별 검토하지
않았다.** 아래 "적용 후" 시뮬레이션은 **1,408건 전부가 승인된다는
가정 하의 전환안(계획)**이며, 실제로는 `apply_tier1_level_adjustment_
8.py`가 요구하는 것과 같은 개별 사람 승인이 먼저 있어야 적용 가능하다
(4절 실행안에서 이 선행 조건을 다룬다).

### 2-3. RULE_A/B 적용 시뮬레이션(제안 전부 승인·적용됐다고 가정) - L1/L2/L3

| 레벨 | mode | 적용 전(문항보유/문항수) | 적용 후(문항보유/문항수) | 증감 |
|---|---|---|---|---|
| L1 | all_candidates | 89 / 324 | 91 / 332 | +2어휘 / +8문항 |
| L1 | auto_only | 67 / 244 | 69 / 252 | +2어휘 / +8문항 |
| L2 | all_candidates | 92 / 346 | 164 / 617 | +72어휘 / +271문항 |
| L2 | auto_only | 6 / 23 | 80 / 296 | +74어휘 / +273문항 |
| **L3** | **all_candidates** | **85 / 316** | **11 / 42** | **-74어휘 / -274문항** |
| **L3** | **auto_only** | **80 / 297** | **8 / 31** | **-72어휘 / -266문항** |

**L3는 RULE_A/B가 전부 적용되면 실제 출제 가능 어휘가 85 → 11(all_
candidates) 또는 80 → 8(auto_only)로 격감한다** - 1,368건의 하향 제안
대부분이 "레벨만 있고 문항은 없는" 어휘들이라 레벨행 수 변화(1,819→451)
보다 문항 기준 손실 비율이 더 크게 체감된다(약 87% 감소).

## 3. 보강 배치를 레벨별 출제에 명시적으로 연결했을 때

**현재 상태 확인(읽기 전용)**: L3 보강 67건 전부 `vocabulary_content_
levels`에 행이 **0건**이고, 문항의 `source_version`도 일반 풀("2.1.29")과
다르다. 즉 **사람이 L3로 확정 판정했어도, 지금 레벨별 출제 선택 조건
(`_select_level_candidates`)은 이 판정을 전혀 반영하지 않는다** - 이중으로
배제돼 있다(레벨행 없음 + source_version 불일치).

**연결 시 추가량(개별 승인 64건 기준, 두 유형을 서로 다른 어휘로 세지
않음 - 64고유어휘·128문항)**:

| 시나리오 | L3 문항보유 어휘 | L3 문항 수 |
|---|---:|---:|
| RULE_A/B 적용 전 + 보강 연결 | 85 + 64 = **149** | 316 + 128 = **444** |
| **RULE_A/B 적용 후 + 보강 연결(all_candidates)** | 11 + 64 = **75** | 42 + 128 = **170** |
| RULE_A/B 적용 후 + 보강 연결(auto_only, 보강을 PROVISIONAL_AUTO로 둘 경우) | 8 + 64 = **72** | 31 + 128 = **159** |
| RULE_A/B 적용 후 + 보강 연결(auto_only, 보강을 REVIEW_BOUNDARY로 둘 경우) | 8 + 0 = **8**(변화 없음) | 31 + 0 = **31**(변화 없음) |

**보강 문항의 level_status를 무엇으로 둘지가 auto_only 공급량을 좌우한다**
- L6 파일럿(phase35) 선례는 신규·미검증 어휘를 `REVIEW_BOUNDARY`로
둬 왔다. 같은 원칙을 따르면 all_candidates에서는 보강 효과가 그대로
살지만, auto_only에서는 보강이 전혀 반영되지 않는다 - **정책 결정이
필요**(4절 실행안에 선택지로 남김).

## 4. 실행안 (RULE_A/B + L0~L3 매니페스트 + 보강 배치 연결, 묶음)

### 선행 조건(이번 턴에 하지 않음, 가장 큰 병목)

RULE_A/B 1,408건 중 1,377건이 아직 개별 사람 검토 전이다.
`apply_tier1_level_adjustment_8.py`와 같은 "개별 승인 → 그 판정만
UPDATE" 원칙을 지키려면, L3 보강에 적용했던 **위험 기반 검수**(전수
요구 안 함, AI 재검토 + 고정 시드 표본)를 이 1,377건에도 적용할지
사용자가 먼저 결정해야 한다 - 범위가 달라 이번 보고서에서 결정하지
않는다.

### 단계 (전부 GATE 패턴: 백업→dry-run→단일 트랜잭션→불변 필드 재검증)

| 순서 | 작업 | 건드리는 테이블/파일 | 기존 세션·응답 영향 |
|---|---|---|---|
| 1 | RULE_A/B 개별 승인(선행조건 완료분만) 적용 - `vocab_level`만 UPDATE(기존 8건 스크립트를 N건으로 일반화) | `vocabulary_content_levels.vocab_level` | **없음** - 이 컬럼은 과거 응답 조회(FK 재조회) 경로에서 쓰이지 않음 |
| 2 | L0~L3 미리보기 매니페스트 재생성(새 버전 파일, 기존 184건 파일은 보존) - 레벨이 바뀐 어휘를 반영 | `data/vocab/pilot_l0l3...manifest_v2.json`(신규), 코드의 `EXPECTED_EXISTING_L0L3_ITEM_COUNT` 상수 | **없음** - 기존 item_id는 그대로, 새 매니페스트에서 빠지는 item은 단지 "향후 신규 세션 후보"에서만 제외됨(과거 세션의 FK는 item_id를 직접 참조하므로 매니페스트 교체와 무관) |
| 3 | 보강 배치(개별 승인분, 1차 29+2차 35=64건, 향후 승인되는 2차 잔여 3건 포함 가능) `vocabulary_content_levels`에 신규 INSERT(`vocab_level=3`, `level_status`는 정책 결정 필요 - 3절 표 참고) | `vocabulary_content_levels`(INSERT만, 기존 행 불변) | **없음** - 보강 배치의 기존 item_id·source_version·qa_flags_json은 전혀 바꾸지 않는다 |
| 4 | `_select_level_candidates`(및 필요 시 `_existing_l0l3_...`)의 `source_version == SOURCE_VERSION` 필터를 `source_version IN (SOURCE_VERSION, GRADE5_L3_BATCH1_SOURCE_VERSION, GRADE5_L3_BATCH2_SOURCE_VERSION)`로 확장 | `app/vocabulary_quiz/routers/multiformat.py`(쿼리 조건만) | **없음** - 기존 일반 출제·L4/L5/L6 파일럿·배치 검수 전용 경로는 그대로, 레벨 모드 선택 쿼리만 넓어짐. 1차/2차 배치 전용 모드(`grade5_l3_batch{1,2}_mode`)는 완전히 별개 코드 경로라 중복 집계 위험 없음(두 경로를 동시에 켜는 요청은 이미 422로 막혀 있음) |

**source_version을 보강 배치 쪽에서 "2.1.29"로 바꿔치기하는 방식은
권장하지 않는다** - item_id를 유지한 채 source_version만 바꿔도, 과거
phase35/batch1 사례에서 확인했듯 의미가 바뀌는 콘텐츠 변경과 동일한
주의가 필요한 데다, 격리 설계(여러 파일럿이 source_version으로 서로
침범하지 않는다는 이 프로젝트의 핵심 불변조건)를 깨뜨린다. 위 4단계
(쿼리 조건 확장)가 데이터 변경 없이 같은 효과를 내는 더 안전한 방법이다.

### 적용했을 때 최종 레벨별 공급량 + 남는 부족 구간(all_candidates 기준)

| 레벨 | 최종(RULE_A/B+보강) | 기존(RULE_A/B 적용 전) 대비 | 비고 |
|---|---:|---|---|
| L1 | 91어휘/332문항 | +2어휘/+8문항 | 큰 변화 없음 |
| L2 | 164어휘/617문항 | +72어휘/+271문항 | L3 하향 유입으로 크게 개선 |
| **L3** | **75어휘/170문항** | **-10어휘/-146문항** | **여전히 부족 - 아래 참고** |

**남는 부족 구간**: L3 보강을 전부 연결해도(64건) RULE_A/B 적용 전
수준(85어휘/316문항)에는 못 미친다 - **10어휘(약 -12%), 특히 문항
수는 146개(약 -46%) 부족**하다. 문항 수 부족이 어휘 수 부족보다 훨씬
큰 이유: 보강 배치는 어휘당 2유형(MEANING_CHOICE·CONTEXT_MEANING)만
있고, 기존 L3 어휘들이 갖고 있던 WORD_FROM_DEFINITION·CONTEXT_CLOZE
유형이 보강에는 전혀 없다(1절 참고) - **유형별 부족**도 별도로 존재:
WORD_FROM_DEFINITION 11개·CONTEXT_CLOZE 9개만 남고 보강으로는 전혀
보충되지 않는다.

`auto_only`는 보강의 `level_status`를 `PROVISIONAL_AUTO`로 두지 않는 한
(3절 표) 8어휘/31문항 수준에 그대로 머문다 - 이 경우 부족 구간이 훨씬
심각하다(-77어휘/-266문항, 전체의 약 10%만 남음).
