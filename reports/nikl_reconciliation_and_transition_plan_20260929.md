### "5,946 vs 5,950" — 재현에 성공했다

`nikl_official_match_full_20260929.csv`(5,950행)와
`nikl_base_level_policy_20260929.csv`(5,950행) 어느 쪽도 파일 자체의
행 손실은 없다(`readlines()-1`로 센 naive 행수와 `csv.DictReader`로
제대로 파싱한 행수가 둘 다 5,950으로 정확히 같고, 공식 목록 원본 xlsx의
개행 포함 정의문(13,932/40,000행, 34.8%)도 이 CSV들의 행 구분에는
영향을 주지 않았다 - 3가지 "파일 손상성" 가설은 전부 기각).

**실제 재현 성공한 경로**: 매칭_카테고리 5개 그룹 중 가장 작은 그룹인
"단일일치(동형이의있음·등급일치)"(4건)를 빼고 나머지 4개 그룹만
더하면:

```
단일일치(5,825) + 다중후보(7) + 표제어만일치(13) + 매칭없음(101) = 5,946
```

**정확히 5,946과 일치한다.** 같은 4건이 "5,829 vs 5,825" 차이의
정체이기도 하다 - `합계(단일일치 5,825 + 동형이의등급일치 4) = 5,829`라는
이전 보고서의 각주식 서술과, 어딘가에서 "단일일치"류 4개 카테고리만
합산한 "5,946"이라는 수치가, **정확히 같은 4건이 어떤 집계에는 포함되고
어떤 집계에는 빠지면서 생긴 같은 원인의 두 증상**이라는 결론이다.

추가로 확인한 원인 제공 요소: 리포트 프로즈("단일일치(동형이의 있으나
등급 일치)")와 실제 CSV enum 값("단일일치(동형이의있음·등급일치)")의
띄어쓰기·어미가 다르다 - 문서를 CSV와 문자열로 직접 대조하면 검색이
빗나갈 수 있는 표기 불일치였다(수치 자체는 옳았지만 불필요한 혼선의
소지).

## 2. 1,997(충돌) / 823(예외) / 1,408(규칙) 집합 연산

**분모 명시**: CONFLICT_1997의 분모는 `nikl_official_match_full`
5,950행 중 `공식_대조_결과`=='충돌'인 부분집합. EXCEPTIONS_823의 분모는
`nikl_base_level_policy_exceptions` 파일 전체 행(=policy CSV의
`review_status`=='INDIVIDUAL_REVIEW_REQUIRED'와 동일 모집단).
RULES_1408의 분모는 policy CSV 5,950행 중
`review_status`=='RULE_PROPOSED_PENDING_APPROVAL'인 부분집합.

| 집합 연산 | 값 |
|---|---:|
| \|EXCEPTIONS_823 ∩ CONFLICT_1997\| | **589** (823건 중 실제로 '충돌' 판정도 받은 것) |
| \|EXCEPTIONS_823 \ CONFLICT_1997\| | **234** (823건 중 충돌은 아니지만 예외 사유가 있는 것) |
| \|CONFLICT_1997 \ (EXCEPTIONS_823 ∪ RULES_1408)\| | **0** (1,997건 중 예외·규칙 어느 쪽도 아닌 잔여) |
| \|RULES_1408 ∩ CONFLICT_1997\| | **1,408** (규칙 대상 전부가 충돌의 부분집합 - 설계대로) |
| \|RULES_1408 \ CONFLICT_1997\| | **0** (설계 오류 없음) |

**"823+1,408=2,231 ≠ 1,997" 간극(234건)의 정체**: 예외 823건 중 234건은
애초에 "충돌"이 아니었다 - 즉 공식 등급과 현재 DB 레벨이 이미 일치하거나
(예: 경계/미매칭/참고전용으로 분류됐거나), 일치하는데도 동형이의·전문분야
위험 때문에 예외로 별도 관리한 항목들이다. 실제 재구성:

```
1,997 = 589(예외이면서 충돌) + 1,408(규칙, 전부 충돌의 부분집합) + 0(잔여)
      = 589 + 1,408 + 0 = 1,997  ✓
```

823건 자체는 "충돌 집합의 부분집합"이 아니라 "충돌·비충돌을 가로지르는
독립적인 위험 태그 집합"이라는 게 정확한 관계다 - 이전 보고서가 이 구조를
명시적으로 보여주지 않아 823+1,408 단순합과 1,997이 다르게 보였을 뿐,
집합 자체에는 결함이 없었다.

## 4. 저장 설계 제안(설계만, 미구현)

**권고안: 별도 참조 테이블**(기존 `vocabulary_content_levels.vocab_level`은
전혀 건드리지 않는 방식).

```sql
CREATE TABLE vocabulary_official_grade_reference (
    content_id           TEXT PRIMARY KEY REFERENCES vocabulary_contents(content_id),
    official_grade        TEXT,      -- '1'..'5' 또는 '다중'/'-'(미매칭)
    proposed_base_level    TEXT,      -- 'L0'..'L2' 또는 '경계(L3~L4)' 또는 NULL(미확정)
    match_method          TEXT,      -- 단일일치/다중후보/표제어만일치/매칭없음
    match_join_fields     TEXT,      -- 예: 'lemma+pos', '표준동형어번호수정 미사용(DB측 식별자 없음)'
    exception_status      TEXT,      -- NULL 또는 교과_전문_의미/동형이의어/뜻이_다를_가능성/레벨격차과대
    source_report_seq     INTEGER,   -- 1160 (국립국어원 자료 페이지 report_seq)
    source_file_sha256    TEXT,      -- '6eec715bca39d1006702da020f5c61a7a1f3db81fdb6101619f68d0b0ff70b53'
    source_version_label  TEXT,      -- '2023년 국어 기초 어휘 선정 및 어휘 등급화 연구'
    computed_at           TEXT,      -- ISO 타임스탬프
    computed_by_script     TEXT       -- 'nikl_base_level_policy.py' 등
);
```

**별도 테이블을 권고하는 이유**: (a) 기존에 실제로 서비스가 읽는
`vocab_level`/`level_status`/`boundary_flag` 컬럼을 ALTER하거나 값에
손댈 필요가 전혀 없어 "적용 후에도 기존 출제 레벨이 바뀌지 않는다"는
요구를 스키마 수준에서 원천적으로 보장한다. (b) `vocabulary_content_levels`에
nullable 컬럼을 추가하는 대안(예: `official_nikl_grade` 등)도 가능하지만,
이미 활발히 조회되는 운영 테이블에 컬럼을 늘리면 매 조회 스키마와
백업/마이그레이션 절차가 더 복잡해지고, "레퍼런스 데이터"와 "서빙
데이터"의 경계가 코드 리뷰 시 흐려질 위험이 있다. (c) 별도 테이블은
git 커밋 가능한 CSV/스크립트 재실행만으로 통째로 재생성·재적재할 수
있어 롤백이 `DROP TABLE` 한 줄로 끝난다 - 마이그레이션 위험이 가장 작다.

**보존해야 할 필드**(전부 위 스키마에 반영): 국립국어원 원본 등급 값
(1~5, `official_grade`), 자료 버전/해시(`source_report_seq`=1160,
`source_file_sha256`=SHA-256 전체값, `source_version_label`), 매칭
방식(`match_method`+`match_join_fields`), 예외 상태(`exception_status`).

**이 절은 스키마 설계 문서일 뿐이다 - `CREATE TABLE`을 실행하지 않았고,
어떤 DB에도 연결해 쓰지 않았다.**

## 5. 서비스 레벨 실제 변경 시 전환 계획(dry-run, 미실행)

### (a) L3 문항 풀 337→64(−81%) 문제

**권고 접근**: RULE_A/B를 한 번에 전면 적용하지 말고, **그림자 계산
기간(shadow period)**을 먼저 둔다 - 4절의 `vocabulary_official_grade_reference`를
실제로 채워 넣고, 신규 세션의 출제 로직에서는 `vocab_level`을 그대로
쓰되 `proposed_base_level`과의 차이를 로그로만 남겨 L2/L3 실제 소모
패턴을 관찰한다. 이후 (i) L2 풀이 거의 2배(332→597)로 늘어나는 것을
먼저 확인해 신규 L2 문항의 다양성·난이도 분포가 실제로 감당 가능한지
확인하고, (ii) L3 풀이 337→64로 급감하는 영향을 완화하기 위해 L3
레벨의 신규 문항(전문 제작 또는 227건 수동 배치 중 개별 검토를 통과한
항목)을 먼저 보강한 다음, (iii) 그제서야 RULE_A/B를 실제 `vocab_level`에
반영한다. 전면 일괄 반영보다 느리지만, "L3 출제가 갑자기 문항 부족으로
막히는" 운영 리스크를 피할 수 있다. **최종 채택 여부는 사용자 결정
사항으로 제안만 한다.**

### (b) L0~L3 미리보기 매니페스트(184건 중 40건 영향) 대책

정책이 실제로 적용되면 `existing_l0l3_manifest_v1.json`의 L2 서브셋
항목 다수가 RULE_B로 L1로 이동해 매니페스트와 라이브 DB가 어긋난다 -
`app/vocabulary_quiz/routers/multiformat.py`의 `_load_existing_l0l3_manifest_rows()`
3중 검증이 이를 드리프트로 잡아 `PilotBatchIntegrityError`(HTTP 500)를
낸다(설계대로 작동하는 것 - 안전장치가 정확히 의도한 대로 걸린다는 뜻).

**권고 순서(레벨 변경과 매니페스트 재생성을 한 세트로 묶기)**:
1. `vocab_level` 변경을 적용하는 시점에 **곧바로** 매니페스트 재생성
   스크립트(9월 29일 세션에서 이미 만든 매니페스트 빌드 패턴 재사용)를
   실행 - 별도 단계로 떼어 놓지 않는다.
2. 재생성 직후 관리자 미리보기 가용성 API(`/existing-l0l3-preview-availability`)를
   4개 레벨 전부 호출해 재검증 - 이전에 구축한 검증 절차 그대로 재사용.
3. 두 단계 사이 시간 동안은 관리자 미리보기가 일시적으로
   `PilotBatchIntegrityError`(500)를 반환할 수 있음을 감안해, **관리자
   전용 기능이므로 학생 영향은 없지만**, 운영 중 이 창을 가능한 한
   짧게(레벨 변경 스크립트 → 매니페스트 재생성 스크립트를 하나의
   배치 작업으로 순차 실행) 유지할 것을 제안한다.

### (c) L4~L6 REVIEW_BOUNDARY·학생 공개 상태 — 이번 계획과 무관함을 재확인

라이브 DB를 다시 읽기 전용으로 조회했다: `MANUAL_LITERACY_L4/L5/L6_MATCH`
227건 전부 `level_status='REVIEW_BOUNDARY'`, `boundary_flag=1`,
`student_exposure=0`, `public_ready=0` - **예외 없이 단일 그룹**으로
재확인됐다. 이 전환 계획의 (a)·(b) 어느 항목도 이 227건의 상태값을
바꾸는 절차를 포함하지 않는다 - RULE_A/B는 `official_grade∈{3,4}`
대상이라 애초에 227건(주로 L4~L6, 공식등급 무매칭·5등급 다수)과
겹치지 않는다.

## 6. 823건 예외 우선순위 재분류(중복 없음)

우선순위 배정 원칙(먼저 만족하는 조건이 최종 등급, 상호 배타):
1. 현재 SOURCE_VERSION='2.1.29' 문항으로 실제 출제 중이면 사유와
   무관하게 **tier1**(실사용 영향 최우선).
2. tier1이 아니고 사유가 동형이의어/뜻이_다를_가능성이면 **tier2**.
3. tier1·tier2가 아니고 사유가 교과_전문_의미/레벨격차과대(학술어휘)면
   **tier3**.
4. 나머지 **tier4**.

| tier | 라벨 | 건수 |
|---|---|---:|
| 1 | 실제_출제_중이며_공식기준과_충돌 | **31** |
| 2 | 동형이의_뜻_위험 | **142** |
| 3 | 상위_교과_의미 | **650** |
| 4 | 당장_출제_영향_없음 | **0** |
| **합계** | | **823** |

**tier4가 정확히 0건인 이유**: 823건은 전부 명시적 위험 사유(교과_전문_의미
/뜻이_다를_가능성/레벨격차과대/동형이의어) 중 하나를 이미 갖고 있어서,
"현재 영향도 없고 위험 사유도 없는" 잔여 카테고리에 해당하는 항목이
구조적으로 존재하지 않는다 - 예외 목록에 오른 것 자체가 이미 최소한의
개별 검토 근거가 있다는 뜻이다.

**"사람이 먼저 봐야 할 고유 건수" 권고**: **tier1의 31건을 최우선**으로
제안한다 - 실제로 지금 학생에게 나가는 문항(2.1.29 프로덕션)의 근거
콘텐츠가 공식 기준과 어긋나 있는 유일한 그룹이라 실사용 영향이 가장
직접적이다. 그다음으로 **tier1+tier2 = 173건**을 근시일 내 검토 대상으로
제안한다(동형이의·뜻풀이 자체의 정확성 문제라 방치하면 문항 품질에
영향을 줄 수 있음). tier3(650건, 대부분 교과_전문_의미)은 "전문 분야
어휘라 학년 등급 자체보다 전문성이 우선 판단 기준이 되어야 하는" 낮은
긴급도 그룹으로, 정책 차원의 일괄 처리(예: 전문분야 태그가 붙은 항목은
전부 개별 근거 없이는 레벨 확정 보류)를 먼저 검토하고 남는 것만 개별
검토하는 방식을 제안한다.
