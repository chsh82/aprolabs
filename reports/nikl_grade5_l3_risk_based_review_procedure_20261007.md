# L3 중등 보강 - 위험 기반 검수 절차 (전수 사람 검수 대체, 2026-10-07 도입)

- 적용 범위: L3 중등 보강 2차부터. 1차(29어휘·58문항)는 이미 전수 사람
  검수를 마쳤으므로 소급 적용하지 않는다(건드리지 않음).
- 목적: 매 배치마다 사람이 모든 문항을 처음부터 끝까지 검수하는 것을
  기본 절차로 요구하지 않고, 기계적 검사 + AI 재검토 + 고정 시드 표본
  재검토로 위험을 선별해 사람의 시간을 "확인이 꼭 필요한 항목"에
  집중시킨다.

## 1. 단계

1. **기존 자동검사 재사용**: 생성 스크립트(`build_grade5_batch{N}_
   dryrun.py`)가 이미 전수에 대해 돌린 기계적 검사(정답 유일성·예문 내
   표제어 존재·정답이 오답에도 포함되는지)를 다시 돌리지 않고 그 결과를
   그대로 가져온다. 이 중 FAIL이 있으면 → **STRUCTURAL_FAIL**로 분류.
2. **생성과 분리된 AI 재검토**(이번에 추가): 콘텐츠를 작성한 사람(에이전트)
   본인이 아니라 별도 검토 단계로 다음을 확인한다.
   - 기계적 스캔: 보기 4개 글자 수 비교 - 정답이 평균 오답의 1.6배 초과
     또는 0.6배 미만이면 "뜻을 몰라도 맞힐 길이 단서" 위험
     → **AI_FLAG_LENGTH_CUE**
   - 직접 재독: 복수 정답 가능성(진짜 동의어 오답 없는지)·오답 관련성
     (같은 의미 분야인지, 무관한 오답 없는지)·문맥 자연스러움(예문이
     어색하지 않은지, 【】 위치가 다른 단어와 겹쳐 혼동을 주지 않는지)
   - 개념 자체가 추상적이라 경계가 미묘하면(오답이 틀렸다는 확신이 있어도)
     → **MEANING_UNCERTAIN**로 신중하게 플래그
   - **이 단계의 PASS는 사람 승인이 아니다** - 기록에도 "AI 재검토"라고
     명시하고 `vocabulary_publish_reviews`에는 쓰지 않는다.
3. **위험 항목 분리**: STRUCTURAL_FAIL·AI_FLAG_*·MEANING_UNCERTAIN 중
   하나라도 해당하면 "위험 항목"(사람 확인 대기열)으로 분류하고, 검수
   화면에 사유를 그대로 보여준다(얼버무리지 않음).
4. **고정 시드 표본**: 위험 항목을 제외한 PASS 풀에서 `random.Random
   (SEED).sample(pool, N)`으로 N건을 뽑는다(N은 배치 크기에 비례해
   정함, 2차는 12건). 좋아 보이는 문항을 고르지 않도록:
   - SEED와 PASS 풀 정의를 코드(`grade5_batch{N}_risk_review.py`)에
     그대로 남겨 재현 가능하게 한다.
   - 두 문항 유형(MEANING_CHOICE/CONTEXT_MEANING)과 서로 다른 어휘가
     섞이도록 추출 후 기계적으로 배정한다(가나다순 정렬 후 유형 번갈아
     배정 등 - 사람이 "이 유형이 더 잘 됐으니 더 뽑자"처럼 개입하지
     않음).
5. **표본 재검토**: 뽑힌 표본을 2단계와 같은 기준으로 다시 본다. 결과
   (PASS/DEFECT_FOUND)와 사유를 기록한다.
6. **반영**: 위 결과를 `vocabulary_multiformat_items.qa_flags_json`의
   `risk_review` 키에 GATE 패턴(백업→dry-run→단일 트랜잭션→불변 필드
   바이트 단위 재검증)으로 추가한다 - 정답/보기/설명 등 다른 필드는
   절대 바꾸지 않는다. `vocabulary_publish_reviews`는 건드리지 않는다.

## 2. 표본에서 결함을 발견했을 때(확산 검사 절차)

표본 재검토(5단계)에서 `DEFECT_FOUND`가 하나라도 나오면, **그 표본
하나만 고치고 끝내지 않는다**:

1. **결함 유형을 분류**한다(예: "같은 오답 패턴을 여러 단어에서 재사용해
   특정 단어 뜻풀이가 다른 단어 오답과 겹침", "같은 빈도로 정답 위치가
   쏠림", "같은 품사군에서 반복적으로 길이 단서 발생" 등).
2. **같은 유형의 검사를 PASS 풀 전체(위험 항목 제외 후 남은 전부)에
   기계적으로 다시 돌린다** - 표본 12건에 그치지 않고, 그 결함 유형을
   탐지하는 스캔 로직을 만들어 35건(2차 기준) 전체에 적용한다.
3. **새로 걸린 항목은 위험 항목으로 재분류**하고, 기존 `risk_review`
   값을 **버전을 올려** 갱신한다(`schema_version` 필드로 구분, 기존
   값을 덮어써 이력을 지우지 않는다 - 왜 바뀌었는지 `risk_reason`에
   남긴다).
4. **표본 크기를 늘릴지 판단**한다 - 결함 발견율이 예상(설계 단계 기준
   0%에 가까움)보다 유의미하게 높으면, 같은 PASS 풀에서 추가 표본을
   (다른 시드로, 사유를 남기고) 더 뽑아 재확인한다.
5. **수정이 필요하면** 콘텐츠·문항(distractor) 데이터를 고치고, 1차
   때와 같은 "비교표"(수정 전/후)를 남겨 무엇이 왜 바뀌었는지 투명하게
   기록한다 - 조용히 덮어쓰지 않는다.
6. 전 과정을 이 저장소의 `reports/`에 새 보고서로 남기고 aprolabs에
   커밋·배포한다.

## 3. 사람 검수와의 관계(원칙 재확인)

- AI 재검토·표본 재검토는 **콘텐츠·문항 승인을 대신하지 않는다**.
  `vocabulary_publish_reviews`에 사람이 직접 판정 버튼을 눌러야만
  "검수 완료"로 기록된다(기존 원칙 그대로, 이번에 바뀐 것 없음).
- 위험 항목은 **반드시** 사람이 직접 확인해야 한다(검수 화면 "⚠ 위험
  항목" 필터).
- 표본에 포함되지 않은 나머지 문항(위험 항목도 아니고 표본도 아닌 것)은
  사람이 원하면 건너뛸 수 있다는 뜻이지, "이미 검증됐다"는 뜻이 아니다 -
  목록에는 여전히 "검수 전"으로 표시된다.
