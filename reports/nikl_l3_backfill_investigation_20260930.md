**재현 결과: 337/64 모두 이전 보고서와 정확히 일치.**

**불일치 1건 발견(투명성 기록)**: 위 337/64는 단일-콘텐츠형 4유형만
집계한 것이다. 실제 앱의 `_select_level_candidates()` 로직은
MATCH_WORD_MEANING(복합형, `source_content_ids_json`의 모든 content_id가
해당 레벨과 일치해야 포함)도 후보에 포함하는데, 재조회 결과 L3에
**MATCH_WORD_MEANING 1건**이 모든 소속 어휘가 L3인 상태로 존재한다.
즉 앱이 실제로 선택 가능한 진짜 후보 풀은 337이 아니라 **338**이다
(1건 차이). RULE_A 적용 후에도 이 1건은 그대로 남으므로 64도 실제로는
**65**가 정확하다. 이전 보고서의 337/64는 "단순 4유형" 정의였고
틀린 것은 아니지만, 앱의 실제 선택 로직 기준으로는 각각 +1건임을
밝힌다.

## 3. L3용 어휘 후보 추가 탐색 (최소 필드 스크리닝)

**(a) DB 내 기존 콘텐츠 중 49건 외 추가 매칭**: 연구 DB 전체
5,950건을 다시 훑어 `official_grade='5'`인 행을 전수 조회한 결과,
**DB 전체를 통틀어 official_grade=5로 매칭된 콘텐츠는 정확히 49건뿐이다
(227건 배치 소속 49건과 완전히 동일한 집합)** — 227건 배치 밖에서는
추가로 발견된 후보가 **0건**이다.

**(b) 공식 목록에 있으나 DB에 아예 없는 진짜 공백**: 공식 5등급
시트는 총 **17,000개** 어휘다. 그중 이 연구 DB에 존재하는 것은
49건(0.29%)뿐이므로, **나머지 약 16,951개는 이 DB에 원천 콘텐츠가
전혀 없는 순수 공백**이다. 이 규모는 신규 어휘 선정·뜻풀이 집필·
문항 제작을 처음부터 다시 해야 하는 작업이라 이번 조사의 범위를
완전히 벗어난다(전수 열거나 뜻풀이 대조는 하지 않았다 — 규모 확인만).

## 4. 4범주 분류 + 실제 사용 가능 문항 수 + 세션 수 계산

후보 풀(49건, 3-(a)에서 추가 발견 0건이므로 49건이 전체)을 상호
배타적으로 4분류했다(우선순위: 예외 사유 있으면 무조건 "검토 필요"
버킷으로, 없을 때만 문항 유무로 재사용/제작 분기):

| 범주 | 어휘 수(content_id) | 실제 사용 가능한 문항 수 |
|---|---:|---:|
| 기존 문항 재사용 가능 | **4** | **8**(MEANING_CHOICE 4 + CONTEXT_MEANING 4) — ⚠️아래 주석 |
| 기존 콘텐츠로 문항 제작 필요 | **13** | 0(제작 전) |
| 의미·전문성 검토 필요(동형이의어) | **32** | 0(검토 전까지 미산입 — 이 중 10건은 문항이 이미 있지만 검토 전이라 카운트하지 않음) |
| 원천 콘텐츠 없음(DB 내) | **0** | — (3-(b)의 16,951건은 별도, 이 표에 포함 안 함) |
| **합계** | **49** | — |

**⚠️ "재사용 가능" 8문항의 중요한 제약**: 이 8개 문항은 전부
`source_version='schema_reading_l4l5_pilot_dryrun_v1'` 또는
`schema_reading_l6_pilot_dryrun_v1'`에 속해 있다 — **현재 학생/관리자
정식 출제에 쓰이는 `2.1.29`가 아니다.** 즉 이미 만들어져 품질 검증을
거친 문항이지만, 실제로 L3 출제 풀에 편입되려면 source_version을
`2.1.29`로 승격하는 별도 절차(이 자체가 DB 쓰기라 이번 범위 밖)가
선행돼야 한다 — "그냥 있는 걸 쓰면 된다"가 아니다.

### L3 반복 없는 10문항 세션 수

**코드 확인(가정 아님)**: `app/vocabulary_quiz/routers/multiformat.py`의
`_select_level_candidates()`→세션 생성은 `random.sample(candidate_ids,
question_count)`로 **item_id 단위 무작위 추출**이며, **어휘(content_id)
중복을 막는 로직이 현재 없다** — 즉 지금 앱은 같은 단어가 한 세션에
두 번 나올 수 있다. 아래 "반복 없는 세션 수"는 사용자가 요청한
**용량 지표**(실제 앱 동작이 아니라 "품질 좋은 세션을 몇 개 만들 수
있는가")이며, distinct 어휘 수를 10으로 나눈 값이 이론적 상한이다.

| 시나리오 | 문항 풀 | 고유 어휘 | 반복없는 10문항 세션 수(상한) |
|---|---:|---:|---:|
| (a) 현재(RULE_A 적용 전) | 337(338) | 91 | **9** |
| (b) RULE_A 적용 후 | 64(65) | 17 | **1** |
| (c) (b) + "재사용가능" 8문항 승격 시(가정) | 72(73) | 21 | **2** |

**RULE_A를 그대로 적용하면 세션 상한이 9개→1개로 급감**하고, 이번에
찾은 "가장 준비된" 보강분(4어휘·8문항, source_version 승격까지
필요)을 전부 반영해도 겨우 **2개**로, 여전히 원래의 22% 수준에
불과하다 — **이번에 발견한 49건 후보만으로는 격차를 거의 메우지
못한다**는 결론이다.

## 6. 제안 실행 순서 (계획만, 실행 안 함)

L3 풀 붕괴(9→1세션) 규모가 이번 49건 보강만으로는 해소되지 않으므로,
**RULE_A를 지금 전면 적용하는 것은 권장하지 않는다.** 구체적 순서
제안:

1. **(가장 작은 확실한 이득)** 4어휘·8문항(재사용가능)에 대해
   source_version 승격 여부를 사람이 결정 — 승격 시 세션 상한
   1→2개로 개선. 이번 범위 밖(실행 안 함).
2. **32건 동형이의어 검토** — 개별 전문가 검토를 거쳐 안전하다고
   확인되는 만큼만 후보 풀에 추가. 전부 통과해도 세션 상한은
   최대 49어휘/4세션 수준까지만 개선 가능(이론 상한, 검토 전이라
   보수적으로 가정).
3. **재평가 게이트**: 1·2단계를 거친 뒤 L3 반복없는 세션 상한을
   다시 계산해, **사전에 합의한 최소 기준치(예: 학생 1주 사용량에
   해당하는 세션 수)에 도달하기 전에는 RULE_A를 `vocab_level`에
   적용하지 않는다** — 임계값 자체는 사용자가 정책적으로 결정할
   사항.
4. **RULE_B(40건, L2→L1)는 L3와 무관**하므로 위 게이트와 독립적으로
   먼저 적용 여부를 검토할 수 있다 — 다만 매니페스트 40건 영향 중
   **10건은 RULE_B 소속**이라, RULE_B만 단독 적용해도 L0~L3
   매니페스트 재생성은 그때 필요해진다.
5. **레벨 변경 시점에는 반드시 매니페스트 재생성을 같은 배치로 묶는다**
   (이전 보고서 제안 유지) — RULE_A든 RULE_B든 어느 쪽을 먼저
   적용하든 동일하게 적용.
6. tier1 "기본 레벨 조정" 8건은 RULE_A/B 게이트와 무관하게 개별
   적용 가능(이미 사람 승인 완료) — 다만 그중 L0~L3 매니페스트
   콘텐츠와 겹치는 항목이 있는지는 실제 적용 시점에 별도 확인 필요
   (이번 조사에서는 확인하지 않음, 8건 규모라 실행 시점에 직접
   대조 권장).
