## 1. 잔여 40건 재구성 + 1차 배치와의 중복 확인

1차 보고서(`nikl_grade5_l3_batch1_admin_load_20261007.md`)가 "121 = 51
보류 + 30 선정 + 40 잔여"로 기록해 둔 그 40건을, 이번에
`data/import/nikl_grade5_200_full_refresh_20261007.csv`(L3 121건,
완료된 조사 재사용 - 재조회하지 않음)에서 **동일한 보류 기준**(다의어
「2」/[Ⅱ] 또는 polysemy_risk_flag, 품사 불명확, 편집 검토 제외 7건 -
전부 1차 보고서에 명시된 그대로 재사용, 새로 판단하지 않음)으로
재구성했다.

**재구성 검증**: 70건(보류 51건 제외) 중 가나다순 상위 30건이 **실제
적재된 1차 배치 30건의 candidate_id와 정확히 일치**함을 직접 대조해
확인(불일치 0건) - 재구성 로직이 맞다는 증거. 나머지 40건(가나다순
하위)이 이번 2차 대상이다.

**1차 배치와의 중복**: 40건의 candidate_id·lemma를 1차 배치 30건 및
벨기에 1건과 전부 대조(`build_grade5_batch2_dryrun.py`의
`cross_check()`) - **중복 0건**(애초에 가나다순으로 상호 배타적으로
나뉜 집합이라 구조적으로 겹칠 수 없음, 기계적으로도 재확인).

## 3. 콘텐츠·오답 작성 (사람이 직접, 외부 조사 없음)

**산출**: `scripts/vocab/grade5_batch2_content.py`(학생용 뜻풀이·예문),
`scripts/vocab/grade5_batch2_distractors.py`(오답 3개·오답 근거·
key_clue), `scripts/vocab/build_grade5_batch2_dryrun.py`(교차 검증 +
문항 생성, 1차 `build_grade5_batch1_dryrun.py`와 동일한 프롬프트
템플릿 재사용).

**오답 설계는 처음부터 1차 v2 기준 적용**(1차처럼 v1→v2 개정 단계를
따로 거치지 않음 - 신규 작성이므로): 같은 의미 분야의 실제 혼동
개념(반대 개념·유의어 차이·위치/범위 혼동·유사 범주 등)만 썼고, 배치
내 다른 단어 뜻풀이를 재사용하는 v1 방식은 처음부터 쓰지 않았다.
`앎`처럼 거의 동의어(지식)로 오답을 만들기 쉬운 항목은 의도적으로
인지 과정이 분명히 다른 개념(탐구/암기/상상)만으로 오답을 구성해
정답 두 개로 보일 위험을 피했다.

**필드 분리(덮어쓰지 않음)**: `official_meaning_short`(공식 원문)와
`student_definition`(학생용 수정안)을 별도 컬럼으로 뒀다.

## 4. 생성과 분리된 검토 — 실제로 2건의 결함을 잡아 수정함

생성 스크립트 1차 실행 결과를 **다시 읽어 보는 별도 검토 단계**에서
아래 2건을 직접 발견해 수정했다(발견 전 상태를 숨기지 않고 그대로
기록):

| 결함 | 발견 경위 | 수정 |
|---|---|---|
| '포장도로' 문맥형 문항에서 【포장도로】 바로 앞에 '비'가 붙어 "비【포장도로】"로 보여 반대말 '비포장도로'와 시각적으로 혼동될 위험 | CONTEXT_MEANING 프롬프트 76건 전수를 직접 읽어 보며 발견 | 예문을 "공사가 끝나자 울퉁불퉁하던 흙길이 매끈한 포장도로로 바뀌었다"로 교체 - 혼동 소지 있는 접두어 인접 배치 제거 |
| 설명문(`explanation`)의 조사가 받침 규칙 없이 "은(는)"/"을(를)" 괄호 병기로 그대로 출력됨(예: "'수시'은(는)...") | 설명문 전수 직접 읽어 확인 | `has_batchim` 기반 `topic_particle`/`object_particle`/`predicate_particle` 함수를 실제로 적용하도록 수정, 재생성 후 76건 전수 재확인 - 1차 배치가 QA 단계에서 실제 겪었던 것과 같은 유형의 버그였음 |

**기계적 자동 검사**(생성 스크립트에 내장, 1차와 동일한 항목):

| 항목 | 결과 |
|---|---|
| 정답 유일성(4개 선택지 서로 다름) | PASS 76/76 |
| 예문에 표제어/활용형 실제 존재 | PASS 76/76 |
| 정답이 오답 목록에도 포함되는 경우 | 0건 |
| 보기 길이 편차(최대가 최소의 3배 초과) | 0건 |
| 오답 텍스트가 배치 내 다른 단어에서 그대로 재사용된 경우 | 0건(v1 방식 미사용의 직접 증거) |

**추가 수동 재확인 2종**(1차와 동일한 항목):
- **동형이의 위험**(homonym_number≠0) 7건(수시·조달·지근지근·치어·
  큰곰·타향·호위하다) - 전부 `official_meaning_short`를 해당
  candidate_id(=이미 특정 동형이의 번호로 고정된 행)에서 그대로
  가져왔으므로 동형이의 오매칭 위험 없음(1차와 같은 결론).
- **반대 개념 오답의 어절 유사도**(열등하다/쾌속/타향 등 4쌍이
  Jaccard ≥0.3) - 전부 "보통의 수준이나 등급보다 OO" 같은 **의도된
  최소 대립쌍**(핵심 단어 하나만 바꿔 정밀한 이해를 요구하는 설계,
  1차 '개축' 항목의 '신축/철거' 오답과 같은 패턴) - 정답 두 개로
  보일 위험이 아니라 의도된 반대 개념 설계임을 직접 재확인.

**중요**: 위 PASS/재확인은 전부 기계적 검사이거나 작성자(에이전트)
본인의 재검토이며, **사람의 문항 승인으로 기록되지 않았다**. 실제
서비스 반영 전에는 1차와 동일하게 관리자 검수 화면을 통한 사람의
직접 승인이 필요하다. 이번 자동검사 통과를 사람 승인이나 실제 학생
난이도 검증으로 표현하지 않는다 - 이 배치로 만들어진 학생 응시
세션은 0건이고, 이번 턴도 응시 테스트를 하지 않았다.
