# L3 2차 위험·표본 검수 후속 처리 - 사람 판정 재확인 (읽기 전용)

- 일자: 2026-10-07
- 범위: 위험 3콘텐츠·표본 12콘텐츠(및 2차 전체 38건)의 최신 사람 판정·
  근거·현재 버전 해시 신선도를 연구 DB에서 **읽기 전용**으로 재확인.
  DB 수정·재적재·배포·학생 공개·momolib 작업은 전혀 하지 않았다(API
  호출 0건). 완료된 테스트(실제 API 전수 테스트)·분류기 실험은 반복하지
  않았다 - 이번엔 `vocabulary_publish_reviews`를 직접 조회하는 가벼운
  SELECT만 수행.

## 1. 위험 3콘텐츠·표본 12콘텐츠 - 중복 제거 + 최신 판정 재확인

**중복 확인**: 위험 집합(`앎·종잡다·축하문`)과 표본 집합(12건) 사이
content_id 중복 **0건**(애초에 표본은 위험 제외 PASS 풀에서만 뽑았으므로
구조적으로 배타적 - 재확인으로도 동일).

**콘텐츠 수 vs 문항 수 구분**:

| 집합 | 콘텐츠 수 | 활성 문항 수(콘텐츠당 2개) |
|---|---:|---:|
| 위험 항목 | 3 | 6 |
| 표본 검수 대상 | 12 | 24(단, AI가 실제로 재검토한 문항은 12개뿐 - 표본은 콘텐츠당 두 유형 중 한쪽만 선정했음. 사람 승인은 콘텐츠 단위라 같은 콘텐츠의 나머지 한 유형에도 동일하게 적용됨) |
| **합계(중복 없음)** | **15** | **30** |

**최신 사람 판정**(해시 신선도 `review_is_stale()`와 동일 로직으로 재확인
- 판정 없음·만료를 승인으로 추정하지 않음):

| 콘텐츠 | 판정 | 신선도 | 검수 시각 |
|---|---|---|---|
| 앎, 종잡다, 축하문(위험 3) | 전부 `APPROVED_CANDIDATE` | 전부 **신선**(해시 일치) | 2026-10-07 01:57~01:59 |
| 표본 12건 전부 | 전부 `APPROVED_CANDIDATE` | 전부 **신선** | 2026-10-07 01:57~02:00 |

15건의 `reviewed_at`이 3분 남짓 사이에 10~90초 간격으로 개별 기록돼
있어, 일괄 스크립트가 아니라 검수 화면에서 한 건씩 직접 승인한 기록으로
판단된다(이 세션은 DB에 쓴 적 없음).

## 2. 수정필요·보류 - 해당 없음(0건)

위 15건 전부 `APPROVED_CANDIDATE`이고 `NEEDS_FIX`/`HOLD`는 **0건**이라,
"같은 결함이 다른 문항에도 있을 가능성 검사"나 수정안 파일 작성은
수행하지 않았다(수행할 대상 자체가 없음).

## 3. 뜻밖의 추가 확인 - 2차 38건 중 35건이 이미 개별 검수됨

지시된 15건(위험+표본)만 확인하는 데 그치지 않고, "실제 확인한 문항과
배치 전체의 검토 상태를 구분해 보존하라"는 지시에 따라 2차 38건 전체의
판정 이력도 함께 조회했다(이것도 가벼운 SELECT 1회, 읽기 전용):

| 상태 | 콘텐츠 수 |
|---|---:|
| `APPROVED_CANDIDATE`(신선) | **35**(위험 3 + 표본 12 + 그 외 20건) |
| `NEEDS_FIX`/`HOLD` | 0 |
| 재검수만료(구버전 승인) | 0 |
| **판정 이력 전혀 없음(검수 전)** | **3**(수시, 숙련, 순서도) |

사용자가 위험·표본 15건에 그치지 않고 **그 외 20건도 추가로 직접
검수**한 것으로 확인된다. 이 사실은 그대로 기록하되, **미검수 3건
(수시·숙련·순서도)에 승인 판정을 추정해 복사하지 않았다** - 이 3건은
여전히 "검수 전"으로 둔다.

## 4. "L3 2차: 자동검사·AI 검토·사람 위험/표본 검수 완료" 기록

지시된 대상(위험 3 + 표본 12 = 15콘텐츠·30문항)은 **전부 유효한
승인후보이고 발견된 결함이 없다** - 이 조건을 충족하므로 아래와 같이
기록한다:

> **L3 2차: 자동검사·AI 검토·사람 위험/표본 검수 완료**
> (위험 3콘텐츠·표본 12콘텐츠, 합계 15콘텐츠·30문항 - 전부
> `APPROVED_CANDIDATE`, 신선, 결함 0건)

이 기록은 **배치 전체(38건)의 개별 승인을 의미하지 않는다** - 3건
(수시·숙련·순서도)은 이 절차의 위험/표본 대상이 아니었고 여전히
개별 승인이 없다(3절 참고, 우연히 사용자가 더 검수한 20건과는 별개로
명확히 구분해 기록).

## 5. 1차 + 2차 합산 집계 (방법론 구분)

| 구분 | 1차(29어휘) | 2차(38어휘) |
|---|---|---|
| 검수 방법론 | **전수 사람 검수**(30건 전부, 보류 1건 제외 29건) | **위험 기반 검수**(전수 요구 안 함) - AI가 위험 3·표본 12만 직접 재검토, 나머지는 사람이 자율적으로 더 봄 |
| 개별 승인(`APPROVED_CANDIDATE`, 신선) | **29/29**(100%) | **35/38**(92%) |
| 미검수(검수 전) | 0 | 3(수시·숙련·순서도) |
| 수정필요·보류 | 0 | 0 |
| 승인된 문항 수(콘텐츠×2) | 58 | 70 |
| 보류(별도 집계, 위 숫자에서 제외) | 벨기에 1콘텐츠(승인 유효하나 매니페스트 제외) | 아멘·파키스탄 2건(콘텐츠 자체 없음) |

**관리자 연구용 활용 가능량**(미해결=검수 전 3건 제외):

| 구분 | 콘텐츠 | 문항 |
|---|---:|---:|
| 검수 완료(승인후보, 신선) - 1차+2차 | **64**(29+35) | **128**(58+70) |
| 미해결(검수 전, 2차만) | 3 | 6 |
| 매니페스트에 기술적으로는 존재하나 구분 필요 | 67콘텐츠·134문항(미해결 6문항 포함, 보류 항목 제외) | |

즉 **DB·매니페스트상 재생 가능한 문항은 134개**(보류 제외)이지만, 그중
**128개(95.5%)만 사람이 실제로 "승인후보"로 확인**했고, 나머지 6개
(수시·숙련·순서도)는 여전히 사람 확인을 기다리는 상태다 - 이 차이를
섞어서 "134개 전부 검수 완료"로 보고하지 않는다.

## 6. 버전 해시 기록(이번에 재확인한 15건)

읽기 전용 조회로 확인한 15건의 `content_hash_at_review`가 현재
콘텐츠·문항 해시와 **바이트 단위로 일치**함을 `review_is_stale()`와
동일한 로직(코드 복제, DB 쓰기 없음)으로 확인했다 - 상세 해시 값은
`vocabulary_publish_reviews` 테이블에 그대로 보존돼 있으며(조회만 함,
수정 없음), 이 보고서는 "일치함"이라는 판정 결과만 기록한다(해시
원문을 중복 기재하지 않음 - 필요 시 DB에서 직접 재확인 가능).

## 7. 수행하지 않은 것(지시대로)

- DB 수정·추가 적재·배포: 전혀 안 함(이번 턴 SELECT만 실행)
- 학생 공개(`student_exposure`/`public_ready`)·momolib 작업: 안 함
- 완료된 실제 API 테스트(격리 DB 사본, 35개 항목)·분류기 실험: 반복
  안 함(이번엔 가벼운 판정 조회만)
- 수정안 파일 작성: 결함이 없어 작성할 대상 없음
