**문항 포맷**: 기존 2.1.29 풀의 실제 MEANING_CHOICE/CONTEXT_MEANING

## 5. QA (생성 과정과 분리된 별도 검사, AUTO_PASS ≠ 사람 승인)

**산출**: `scripts/vocab/qa_grade5_batch1_dryrun.py`(생성 스크립트와
완전히 다른 파일 - 같은 코드로 자기 검증하지 않음).

| 항목 | 방식 | 결과 |
|---|---|---|
| 정답 유일성(한 문항 안 4개 선택지가 서로 다른가) | 기계적 | **AUTO_PASS 60/60** |
| correct_option 인덱스 일치(생성 버그 검출) | 기계적 | **AUTO_PASS 60/60** |
| 오답 의미 중복(어절 자카드 유사도 ≥0.2) | 기계적 근사 | AUTO_FLAG 2쌍(도시민/범행자 관련 4건) - **사람이 직접 재확인**: "도시에서 사는 사람." vs "범죄를 저지른 사람." 둘 다 끝 단어 "사람."만 같아서 걸린 거짓 양성, 실제 의미 중복 아님 |
| 동형이의 혼동 위험(homonym_number≠0) | 기계적 플래그 | 6건(단음·대소·뒤룩뒤룩·면회하다·변성기·상용) - 저작자 재확인: 전부 그 어휘의 가장 널리 쓰이는 뜻과 일치, 뚜렷한 혼동 후보(명시·볼트)는 이미 3절에서 제외 |
| 조사(을/를·이/가·은/는·과/와·로/으로) 호응 | 기계적(받침 규칙) | 1차 실행에서 생성 스크립트의 실제 버그 발견(아래 참고) → 수정 후 재실행 결과 AUTO_FAIL 10건은 전부 검사기의 거짓 양성(동사 활용형 "-는"을 조사로 오인) - 사람이 10건 전부 재확인해 문법 오류 아님을 확인 |
| 연령/표현 적합성 | 저작자 재검토(3절 선정 단계) | 7건 제외(3절 표 참고) - 여기서 다시 판단하지 않고 그대로 인용 |

**생성 스크립트 버그를 QA 단계에서 실제로 잡은 사례(투명성 기록)**: 1차
생성 결과의 설명문이 받침과 무관하게 "'개축'는 '...'(이)라는 뜻입니다."
식으로 조사를 고정 출력하고 있었다(개축은 받침이 있어 '은'이어야 함). QA
스크립트의 조사 검사가 처음엔 이 오류를 놓쳤다(인용부호가 글자와 조사
사이에 끼어 있어 단순 인접 문자 검사가 못 잡음) - 검사 자체를 인용부호
패턴까지 보도록 고친 뒤, 생성 스크립트에 받침 기반 조사 선택 함수(은/는,
을/를, (이)라는)를 추가해 재생성했다. 재실행 결과 이 유형의 오류는 전부
해소됐고, 남은 10건의 AUTO_FAIL은 전부 "쌓는/돕는/없는/있는" 같은 **동사
활용형**(관형사형 어미 "-는")을 조사로 착각한 검사기 자체의 거짓
양성임을 직접 재확인했다(동사 어간 뒤 "-는"은 받침 규칙이 적용되는
조사가 아니라 활용형이라 이 검사 대상이 아님).

**중요**: 위 AUTO_PASS/AUTO_FLAG는 전부 기계적 검사이거나 저작자 본인의
1차 재검토이며, **사람의 문항 승인으로 기록되지 않았다**(그런 필드도
만들지 않았다). 실제 서비스에 반영하려면 기존 공개검토 화면
(`/vocab-publish-review/`)과 같은 별도 검수자 승인 절차가 반드시
필요하다 - 이번 산출물은 그 절차에 넣기 전 단계의 초안일 뿐이다.
