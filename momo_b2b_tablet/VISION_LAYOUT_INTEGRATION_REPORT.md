# qaref 연결 + compare 후보 플래그 + 12% 내역 + 선잇기 15건 재추출 + 초안 5종 재생성 (2026-09-25)

## 1. reference를 qaref로 연결

`layout/step2.py`는 이미 `qaref` 페이지 타입(참고표+제시문+문항)을 지원하고
있었다(SPEC §2.1의 `ref{title, img?, rows[{n,v}|{gap:true}], note?}`) -
기존에는 `doc.hanja_glossary`에서 "제시문이 분리된 첫 문항에 붙인다"는
휴리스틱으로만 채워졌다. 이번에 vision 쪽을 연결했다:

- `NormalizedQA`에 `ref_table` 필드 추가(기본 None - 기존 파이프라인은 절대
  안 채움).
- `vision_parse/build_normalized.py`가 vision의 `reference_table` shape
  항목을 실제 페이지 번호 기준으로 **바로 다음 discussion_qa 문항**에 연결한다
  - 추측이 필요 없다(원본이 어느 페이지에 있었는지 이미 안다).
- **중요한 실측 발견**: `layout_shape='reference_table'`은 `item_type`과
  독립적이다. 열하일기 한자 표는 `item_type='vocab'`인데 shape만
  reference_table이고, 같은 문서 2쪽의 배경 설명 3건은 `item_type=
  'discussion_qa'`인데도 shape가 reference_table이다(답란 없는 순수 소개
  문단). `item_type='vocab'`인 것만 진짜 참고표로 보고 연결하고, 나머지는
  질문도 참고표도 아닌 소개 문구라 페이지를 만들지 않고 건너뛴다.
- 검증: 열하일기(L9-Q3-W07)를 다시 생성하니 `type: "qaref"` 페이지가 정확히
  나왔고, `ref.rows`가 골든 샘플(`samples/L9-Q3-W07.layout.json`)과 **글자
  단위로 완전히 일치**했다(상징하다(象徵--), 유추하다(類推--) 등).

## 2. compare 후보 플래그

`table_answer` 2행(순번 없음)을 `table`로 매핑하되, 검수용 플래그를 추가로
남긴다: "2행 표(table)로 매핑했지만 라벨이 대립하는 두 항목처럼 보여 compare
후보임 - 검수에서 필요하면 compare로 전환". 야옹아 1번이 이 플래그를 달고
`table`로 생성됨을 확인했다. `correction_log`의 `form_change` 이력은 검수
화면에서 실제로 폼을 바꿀 때 기존 메커니즘(`edition/store.py patch_edition`)
이 그대로 기록한다 - 이번에 추가 구현은 필요 없었다.

묶임"(21건)은 이미 알려진 페이지 경계 문제(`PARSING_METHOD_COMPARISON.md`)
와 같은 범주다.

## 4. 선잇기(매칭형) 15건 재추출 — 완료

`vision_parse/extract.py` 프롬프트에 "매칭 문제는 왼쪽(blanks)·오른쪽(table)
둘 다 뽑아라" 지시를 추가하고, 15개 문서를 `--force`로 재실행했다.

```
15/15 성공, 파싱 오류 0건
131쪽, 처리시간 1,239초(20.7분)
토큰: in 630,503 / out 107,843
비용: 약 $3.51
```

**검증**: 15건 전부 "선으로 이어" 질문에 `table_json`이 채워졌다(이전
0/15 → 15/15). 예시(`L1-Q3-W04`):
```
blanks: ["봉오리", "뒤통수", "널따랗다", "성큼", "쪼그리다"]
table:  [["꽤 넓다."], ["다리를 높이 들어 크게 떼어 놓는 모양."],
         ["머리의 뒷부분."], ["(꽃)망울만 맺히고 아직 피지 아니한 꽃."],
         ["팔다리를 오그려 몸을 작게 옴츠리다."]]
```
왼쪽·오른쪽 순서가 서로 안 맞을 수 있다(원본 자체가 무작위로 섞어 놓은
매칭 문제라 의도된 것 - 프롬프트에도 "순서를 맞추려 하지 말라"고 명시함).
**어느 낱말이 어느 뜻과 실제로 짝인지 판정하는 것은 이번 범위 밖**이다
(LLM이 선을 "본다"기보다는 텍스트만 옮긴 것 - 매칭 판정은 검수 또는 별도
작업으로 남긴다).

## 6. [2026-09-26 추가] 원본 이미지 연결 끊김 - 회귀 수정

야옹아(edition 7) 검수 중 12쪽 동물등록증 등 원본 삽화가 빠진 게 발견됐다.
원인: 비전 초안은 `table`/`compare`/`choice`/`choiceList` 폼으로 분류되는
문항이 기존 DB 기반 초안보다 훨씬 많은데, `layout/step2.py`는 이 폼이면
원본 삽화 유무와 무관하게 무조건 `wide=True`(전체 폭 답란)로 이미지 슬롯
자체를 건너뛰고 있었다. DB 기반 파이프라인에서는 이런 폼이 드물어 드러나지
않던 문제였다.

**수정**: `_original_image_for_qa()`를 추가해, wide로 내려가기 전에 같은
`source_page`에 원본 삽화가 있는지 먼저 확인 - 있으면 슬롯을 우선하고,
없을 때만 wide로 내려간다. 골든 테스트(L9-Q3-W07 문항7 등) 전부 회귀 없음
확인 후 커밋(`1d0c808`).

**5종 전체 - 수정 전(edition 7~11) vs 수정 후(edition 12~16), 같은 비전
초안 안에서 직접 비교**:

| doc_id | 원본이미지 슬롯(수정 전→후) | wide로 빠진 문항(수정 전→후) |

| L5-Q3-W10(긴긴밤) | 0 → 0 | 1 → 1 |
| L9-Q3-W07(열하일기) | 3 → 4 | 7 → 6 |
| L5-Q4-W02(두근두근 한국사) | 0 → 5 | 5 → 0 |
| L7-Q1-W08(젊은 예술가의 초상) | 2 → 2 | 3 → 3 |

기반 초안 자체가 없어 이번에 비전으로 처음 만들어졌는데, 수정 전 상태로
