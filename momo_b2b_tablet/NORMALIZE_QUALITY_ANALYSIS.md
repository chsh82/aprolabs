# 정규화 품질 분석 (2026-09-23)

검토 결과("조판은 문제없고, 발견된 오류는 대부분 파싱 오류")를 이어받아, 실제 오류를

단계를 **momo_book.db 전체 305건**에 대해 실행해 플래그를 집계했다.

## 1. 오류 유형 분류 + 실제 사례

### (a) 원본 DB는 정상인데 정규화가 못 잡은 것

**아직 열려있는 것(전체 305건 기준 건수)**

| 건수 | 패턴 |
|---|---|
| 349 | 질문 자체 앞머리에서 독해유형은 뽑았지만, 인용문과 질문이 아직 한 덩어리 |
| 79 | unknown 행에 제시문만 있고 질문이 없음(사람/LLM이 질문을 새로 만들어야 함) |
| 5 | `writing_guide`에 STEP 질문이 리드와 섞여 있음 |

**사례 1** (L9-Q3-W07, 문항 2) — `question_text`:
> "[분석적 / 추론적 독해] "겉모습이 이러하니 세상에 진기한 놀잇감이라 할 만하다. 그러나 내가 이를 통해 슬퍼하는 것은 다른 데 있다. …" (174) …돌이켜 보면 우리가 살아가는 방식도 이와 비슷하지 않을까요? 여러분이 겉모습만으로 판단했다가 나중에 그 진짜 모습을 알게 된 경험이 있다면 이야기해 볼까요?"

독해유형 라벨은 뽑혔지만, 인용문(따옴표+쪽수)과 실제 질문이 한 문자열 안에 그대로
남아 있다. 규칙으로는 인용 경계를 안전하게 못 자르고(따옴표 안에 마침표·물음표가
섞여 있어 정규식이 문장 경계를 오판할 위험), LLM 분리가 필요하다(SPEC §4 그대로).

**사례 2** (L5-Q4-W02, 문항 4, **이번에 고친 버그의 원인 사례**) — 원본 `discussion_qa`
id=435: `ui_type='unknown'`인데 `excerpt_text`="언해본에는 세종이 훈민정음을 만든
까닭을…", `question_text`="다음은 [훈민정음] 언해본을 지금의 말로 옮겨 놓은
거예요. … 나라의 말이 중국의 말과 달라 서로 통하지 아니하다. …" 로 **둘 다 이미
완전하게 채워져 있었다**. 기존 코드는 `ui_type != 'unknown'`인 행만 "진짜" 행으로
취급해, 이 행을 raw_text 기반 "제시문 후보" 경로로만 처리하면서 `question_text`를
통째로 버리고 "질문 없음"으로 잘못 플래그했다. → **수정**: `excerpt_text`와
`question_text`가 모두 자체적으로 채워진 unknown 행은 `text_long`으로 승격해
그대로 쓰도록 고쳤다(2절 참고). 305건 전체에서 **148건**이 이 패턴이었다.

**사례 3** (blanks, 다수 문서) — `ui_config`가 `{"blanks": ["조선이 말 다루는 법의
단점", "나의 경험"]}`처럼 **답란 라벨은 구조화**돼 있지만, 그 라벨에 대응하는
독립된 질문 문장은 DB에 없고 하나의 긴 `question_text`에 두 질문이 섞여 있다.
라벨은 정상이므로 (a)지만, 완전한 분리는 규칙이 아니라 LLM 생성이 필요하다(SPEC
§4 "하위 질문 파생").

### (b) 원본 DB 자체가 깨진 것 (PDF 파싱 단계 문제)

| 건수 | 패턴 |
|---|---|
| 121 | 한글 사이 공백 3개 이상 연속 - 어순/단어 자체가 뒤섞임 |
| 136 | 이미지 저해상도(300px 미만) |
| (79 중 일부) | 제시문만 있고 질문 없음 - 일부는 실제로 PDF에서 질문 자체가 누락된 것일 수 있음(샘플 대조 필요) |

**사례 1** (L5-Q3-W10 "긴긴밤", `excerpt_text` 원문 그대로):
> "혼자서는 코뿔소가 될 수 없었다 . 노든이 코끼리로 살 수 있었던 것은 코끼리들이 있 었기 때문이고, 코뿔소가 되기 위해서는 다른 코뿔소들이 있어야만 했다 ."

**사례 2** (같은 문서, 더 심한 경우):
> "“뿔이 없긴 하지만그래도,    코뿔소야그들이.    잘라 냈어같이.   살던 내 친구 앙가부가 뿔 사냥꾼에게 당했거든이제.   나와 같은 코뿔소는 더 이상 없대내가.   마지막 남은 하나 래우습지.        ?"

"그래도," 뒤에 와야 할 "코뿔소야"가 엉뚱하게 다음 문장 조각과 붙고("코뿔소야그들이"),
공백이 3~9개씩 불규칙하게 남는다 — 단순 띄어쓰기 실수가 아니라 **PDF에서 텍스트를
뽑을 때 두 개 이상의 텍스트 흐름(본문+말줄임 강조 등)이 어긋난 순서로 병합된 것으로
보인다**. `text_repair.py`가 이미 "단어 내부가 뒤섞인 건 규칙으로 못 고친다"고
명시하고 있고, 실제로 규칙 기반 복원은 문장부호 공백 정리 정도만 하고 원문을 그대로
플래그만 남긴다. **이건 정규화가 아니라 `momo_book_db`의 원본 PDF 파싱 파이프라인
(`parser.py`)을 손봐야 하는 문제**라 이번 프로젝트 범위 밖으로 분리한다(2-2절).

**사례 3** (L9-Q3-W07 표지, L5-Q3-W10 배경 이미지): 204×299px, 225×225px로 추출됨 —
인쇄 300dpi 기준(SPEC §3.5.4) 미달. PDF에서 이미지를 낮은 해상도로 추출했거나, 원본
자체가 저해상도다.

### (c) 내용은 맞는데 필드 배치가 틀린 것

전부 **정규화 규칙이 이미 자동으로 고치고 있다**(아래는 305건 전체 기준, 전부
"해결됨" 감사 로그이지 열린 문제가 아니다):

| 건수 | 패턴 |
|---|---|
| 148 | unknown 행인데 excerpt_text·question_text가 이미 다 채워짐 (이번에 고친 것) |
| 114 | unknown 행에서 독해유형 라벨 추출 |
| 110 | unknown 행의 raw_text가 더 길어 excerpt_text로 채택 |
| 80 | 같은 그룹의 다른 소문항이 가진 제시문을 공유 |
| 2 | 질문이 다른 order_no 행에 컬럼 밀림으로 붙어 있던 것을 복원 |

**사례 1** (SPEC §4가 원래 예로 든 것과 동일한 패턴, L9-Q3-W07): `order_no=5`의 행
(id=3440)은 `excerpt_text=NULL`이고 제시문 전체가 `question_text` 컬럼에 들어가
있으며 정작 질문이 없다. 반면 `order_no=19`의 행(id=3448)에는 한자 용어
"표현하다(表現--)" 뒤에 `order_no=5`에 속해야 할 진짜 질문 2개(`1) '상기'에서
코끼리는…`, `2) '소, 말, 닭, 개의 습성을…`)가 붙어 있다. → 규칙이 한자 용어는
`hanja_glossary`로, 질문 2개는 원래 자리(`order_no=5`)로 복원해 `5-1`/`5-2`로
재조립한다(골든 테스트로 고정됨).

**사례 2** (L2-Q2-W08): `order_no=1`의 unknown 행 `raw_text`="사실적 / 분석적 독해
은비는 조심스레…"에서 독해유형 라벨("사실적 / 분석적")만 뽑아 진짜 행의
`reading_type`에 채우고, 나머지 서술문은 버린다(이 unknown 행은 excerpt_text가
없으므로 (a) 사례처럼 승격시키지 않음 - 2절의 판별 기준 참고).

## 2. 정규화 규칙 보강

### 2-1. 이번에 고친 것 (`normalize/discussion_qa.py`)

1절 (a)-사례2의 버그를 고쳤다. 판별 기준은 **"unknown 행이지만 `excerpt_text`와
`question_text`가 자기 스스로 채워져 있는가"**로 잡았다 — `question_text`에
물음표가 섞여 있는지만으로는 판별할 수 없다(L2 문서의 정상 unknown 행도 서술문
안에 "이게 설마 꿈은 아니겠지?" 같은 수사적 물음표가 섞여 있어서, 처음에는 이
기준으로 잘못 승격시켜 골든 테스트 5건이 깨졌다 — `excerpt_text` 자체 보유 여부로
좁혀서 해결). 305건 전체·모든 골든 테스트(정규화 30, 골든비교 63, 조판골든 82,
조판규칙 29, edition_store 32 — 전부 실패 0건)로 검증했다.

### 2-2. 규칙으로 추가 보강 가능한 것 (다음 작업 후보, 이번에는 미착수)

- **"독해유형은 뽑았지만 인용문·질문 미분리"(349건)**: `_LABEL_RE`처럼 안전한
  정규식만으로는 인용부호 내부의 마침표/물음표 때문에 경계를 확신할 수 없다.
  SPEC §4 방침대로 **LLM 보조 + `confidence` + 플래그**가 필요하다 — 이번 세션에서는
  실제 API 호출(비용 발생)까지는 진행하지 않았다. 프롬프트 설계·모델 선택·305건
  전체 호출 여부는 사용자 확인 후 진행하는 게 맞다고 판단했다(예상 호출 349회 +
  blanks 분리 등 추가 시 400건 이상 - 비용/시간 규모를 먼저 보고).
- **blanks 개별 질문 분리**: 마찬가지로 LLM 생성 필요, 위와 함께 설계하는 게 효율적.
- **"제시문만 있고 질문 없음"(79건)**: 이 중 몇 건이나 실제로 PDF에 질문이 있었는지
  (파싱 미스, (b)) vs 정말 원본에 없는지(사람이 새로 써야 함, (a)) 표본 확인이
  먼저 필요하다 - 지금 자동으로 나눌 신호가 DB에 없다.

## 3. (b) 원본 PDF 파싱 파이프라인 문제 — 별도 과제로 분리

`momo_book.db`를 만드는 `momo_book_db/parser.py`(PDF→JSON)를 고쳐야 하는 범위라
이 프로젝트(정규화·조판·검수)와 분리한다. 목록만 정리:

1. **어순/단어 뒤섞임 (121건, 305건 중 상당수가 L5-Q3-W10류 고학년 문학 지문에
   집중)** — 두 텍스트 흐름이 잘못된 순서로 합쳐지는 것으로 보임. `pdfplumber`/`fitz`
   텍스트 추출 시 좌표 기준 정렬 로직을 점검해야 함. 재현 문서: L5-Q3-W10(긴긴밤).
2. **저해상도 이미지 136건** — 원본 PDF에서 이미지를 추출하는 DPI/방식 점검 필요.
   인쇄용(SPEC §3.5.4, 300dpi) 기준 재검토.
3. **"제시문만 있고 질문 없음" 79건 중 일부** — 표본 확인 후 파싱 누락으로 판명되면
   이 목록에 추가로 편입.
