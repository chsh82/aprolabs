# 파싱 방식 비교 실험 — 방식 A(기존) vs 방식 B(비전 모델) (2026-09-24)

LLM 분리 작업(349건 전량 적용)은 보류하고, "파싱을 새로 하는 게 나은지" 판단을
위한 비교 실험을 먼저 수행했다. 코드 변경은 없다 — 실험 스크립트는
`momo_b2b_tablet/normalize/llm_split.py`와 별개로, 이번 실험 전용 스크립트를
세션 스크래치패드에서만 실행했다(리포지토리에 커밋하지 않음).

## 0. 실험 방법

- **대상**: `L5-Q4-W02`(두근두근 한국사 1권 2주차, 요청된 문서) + 검증을 위해
  추가로 2개 문서에서 각 1페이지씩 보충 확인(아래 1-3절 참고 — 이유는 1절 끝에
  설명).
- **원본 PDF 확보**: `documents.source_file`에 기록된 경로(`D:\...`)가 이번에는
  실제로 존재했다(현재 외장 드라이브가 연결되어 있음 — 상시 보장되는 조건은
  아니다, 4절 참고). SHA-256 해시를 `documents.source_hash`와 대조해 momo_book.db가
  가리키는 것과 **동일한 파일**임을 확인한 뒤 사용했다.
- **방식 A**: 현재 `normalize/run.py` 정규화 결과(momo_book.db 원본 → 파서 →
  정규화 규칙).
- **방식 B**: `PyMuPDF`로 PDF 각 페이지를 150dpi PNG로 렌더 → `claude-sonnet-5`에
  이미지 1장씩 전달 → 정규화 레코드와 같은 필드(제시문/질문/빈칸 라벨/표/선택지/
  쪽수) + `layout_hint`(시각 구조 힌트: 인용상자/표/번호목록/서약서형 테두리/
  말풍선/답란 줄 수)를 JSON으로 요청. 원문 글자를 고치지 말라고 명시.

## 1. 비교 결과 — L5-Q4-W02 (9페이지)

**중요한 전제**: L5-Q4-W02는 이번 정규화 버그 수정(9/23~24 세션) 이후, 현재
**"349건"(인용문·질문 미분리) 플래그가 0건**이다 — 원본 DB의 이 문서 discussion_qa
행들이 애초에 excerpt_text/question_text가 잘 분리된 형태였기 때문이다. 또한
"어순 뒤섞임" 플래그도 0건이다. 즉 **이 문서 자체는 기준 1·2의 문제를 현재
보여주지 않는다** — 사용자가 지목한 "오류가 여러 종류"는 이번에 고친 "제시문만
있고 질문 없음" 버그, OX/어휘 결손, 저해상도 이미지였다(momo_b2b_tablet의
`NORMALIZE_QUALITY_ANALYSIS.md` 1-3절 참고). 그래서 기준 1·2는 **이 문서만으로는
검증이 안 돼 다른 두 문서에서 대표 페이지 1장씩 보충 확인했다**(1-3절). 기준
3·4·5는 L5-Q4-W02로 충분히 비교된다.

### 기준 3 — 표와 번호 목록이 구조로 잡히는가: **B가 명확히 우세**

2페이지(어휘) 비교:

| | 방식 A | 방식 B |
|---|---|---|
| 추출 내용 | `봉기: 벌 떼처럼...`, `대항하다: 굽히거나...` 등 **단어→뜻풀이만** | 단어·쪽수·뜻풀이·**"문장 만들기" 빈칸 열까지 표 구조 그대로**: `{headers: [단어,구분,내용], rows: [[봉기(115페이지),뜻,...], [봉기(115페이지),문장,""], ...]}` |

방식 A는 `vocabulary` 테이블 스키마 자체가 "단어+뜻풀이"만 담게 설계돼 있어서,
원본 페이지에 있는 **"이 단어로 문장을 만들어 보세요"라는 별도 연습 문항(빈칸
4개)을 통째로 놓친다** — 정규화 규칙의 한계가 아니라 애초에 파서가 그 구조를
테이블로 안 뽑는다. 방식 B는 이미지를 보고 표 전체(단어/뜻/문장 3열)를 그대로
구조화했다.

choice_ab류(예: "이해할 수 있어요! / 반란은 옳지 않아요!") 문항은 둘 다 구조를
놓치지 않았다 — A는 `ui_config.options` 리스트, B는 `table.headers` — 표현 방식만
다르고 정보 손실은 없었다.

### 기준 4 — 위젯 신호(layout_hint)를 얻을 수 있는가: **부분적, 프롬프트 보강 필요**

방식 A도 이미 `ui_type`(choice_ab/text_short_multi/text_long/text_short 등, 원래
`parser.py`의 LLM 분류 결과)으로 위젯 신호를 갖고 있다. 이번 프롬프트로 뽑은
`layout_hint.shape`는 답란이 있는 문항 대부분을 뭉뚱그려 `"표"`로 반환해서, A의
기존 `ui_type` 구분(choice_ab vs text_short_multi vs text_long)보다 **더 세밀하지
않았다** — 이번 프롬프트 설계의 한계다. 다만 `blank_lines`(글쓰기 문항 5번=5줄,
표지=0줄)처럼 **A에는 아예 없는 새 신호**도 있었다 — 답란 크기를 조판 단계에
바로 활용할 수 있는 정보다. **결론: layout_hint 자체는 유용한 축이 맞지만,
"표" 카테고리를 세분화하도록 프롬프트를 다시 설계해야 위젯 자동 선택에 실질
도움이 된다.**

| 페이지 | 처리 시간 | input 토큰 | output 토큰 |
|---|---:|---:|---:|

| 2 (어휘, 표 6개) | 14.2s | 3,779 | 1,492 |

input 토큰이 페이지마다 거의 고정(3,779)인 건 이미지 자체가 대부분을 차지하기

## 2. 방식 B가 실제로 해결하는지 확인한 보충 사례 (다른 문서 1페이지씩)

L5-Q4-W02가 기준 1·2를 테스트하지 못해서, **같은 해시 검증 절차**로 두 문서의
대표 페이지를 추가로 확인했다(요청 범위를 벗어나지 않는 보충 확인 — 전체 재실험은
하지 않았다).

### 기준 2 — 어순 뒤섞임이 사라지는가: **L5-Q3-W10(긴긴밤) 4페이지, B가 완전히 해결**

방식 A(원본 DB `excerpt_text` 그대로, 이번 세션 초반에 (b) 사례로 보고한 것과
동일):
> 둘은 동물원 안에서 익숙하고 안정된 것들에 둘러싸여 함께 지냈다**살면서**.    걱정이라 는 것도 해 보지 않았다 . 심지어 치쿠의 한쪽 눈이 잘 보이지 않게 되었을 때도 천하태 평이었다**그런**.   그들에게 처음으로 익숙하지 않고 두려운 것이 생겼는데**바로**,   버려진 알 이었다**치쿠와**.    윔보는 버려진 알을 품게 되면서 오만가지 걱정을 하기 시작했다 .

방식 B(같은 페이지, 비전 추출):
> 둘은 동물원 안에서 익숙하고 안정된 것들에 둘러싸여 함께 지냈다. 살면서 걱정이라는 것도 해 보지 않았다. 심지어 치쿠의 한쪽 눈이 잘 보이지 않게 되었을 때도 천하태평이었다. 그런 그들에게 처음으로 익숙하지 않고 두려운 것이 생겼는데, 바로 버려진 알이었다. 치쿠와 윔보는 버려진 알을 품게 되면서 오만가지 걱정을 하기 시작했다.

**완전히 정상 문장이다.** 같은 페이지의 더 심한 사례("뿔이 없긴 하지만그래도,
코뿔소야그들이." 등, 세션 초반 (b) 사례2로 보고한 문장)도 B에서 정상 문장
("뿔이 없긴 하지만, 그래도 코뿔소야. 그들이 잘라 냈어. …")으로 나왔다. 어순
뒤섞임은 **글자 순서 추출(텍스트 레이어) 단계의 문제**였고, 이미지를 통째로
읽는 비전 방식은 애초에 그 추출 경로를 타지 않으므로 구조적으로 재발하지 않는다.

### 기준 1 — 제시문·질문 분리: **L9-Q3-W07(열하일기) 3페이지, 여러 개 인용도 정확히 분리**

같은 페이지에 인용이 2회씩 등장하는 두 문항을 방식 B가 모두 올바르게 갈랐다
(예시 1개):
> **excerpt_text**: "황제의 명령도 없는데 어찌 받을 수 있겠습니까. 마땅히 돌려보냄이 옳은 줄 압니다." (164) / "거참, 황제의 분부가 고약하기 짝이 없네. … 명나라 때야 어디 이런 일이 있었겠어?" (233)
> **question_text**: 여정에서 청나라 황제를 대하는 사절단의 태도는 사뭇 이중적입니다. … 사절단은 왜 청나라 황제에 대한 이런 이중적 태도를 갖게 된 것일까요? 여러분은 사절단의 이중적 태도에 대해 어떻게 생각하나요?

인용 2개 + 쪽수(164, 233) 모두 제시문 쪽에 붙었고, 질문만 정확히 분리됐다 —
5절에서 이미 검증한 30건 LLM 분리(텍스트만 입력)와 별개로, **이미지 입력만으로도
같은 품질의 분리가 나온다**는 뜻이다. 다만 `page_number` 필드에 실제 발췌문에
없는 "(257~258)"이 하나 더 포함돼 있었다 — 페이지 안의 다른 각주/문항 쪽수를
같이 주워왔을 가능성이 있어(원문을 직접 대조하지 않아 확정은 못 함) **경미한
신뢰도 이슈로 기록**한다. 이번 30건 LLM 분리 실험(`SAMPLE_SPLIT_REVIEW_30.md`)의
`verify_no_rewrite` 같은 자동 검증이 비전 방식에도 필요하다.

## 3. 305건 전체를 방식 B로 다시 뽑을 경우 예상 비용·시간

실측치(momo_book.db, 읽기 전용 조회로 확인, API 호출 없음):

```
전체 305건 소스 PDF 총 페이지 수: 2,712쪽 (평균 8.89쪽/문서, 중앙값 9쪽, 최소 6~최대 13)
현재 305건 전부 source_file 경로가 실제로 존재함(현재 외장 드라이브 연결 상태 기준)
```

실측 단가(11페이지 호출 평균, `claude-sonnet-5`):

```
페이지당 평균: input 3,779 토큰 / output 657 토큰 / 처리시간 9.0초
```

Sonnet 계열 공개 단가(확인 필요 - 실행 시점 최신 단가로 재검증 권장) 기준
$3/M input, $15/M output 가정 시:

```
페이지당 비용 ≈ $0.021
305건(2,712쪽) 전체 ≈ $57 (약 8만 원)
순차 처리 시간 ≈ 2,712쪽 × 9.0초 ≈ 6.8시간
동시 10건 병렬 처리 시 ≈ 약 40분 (계정 실제 rate limit 미확인 - 사전 확인 필요)
```

**주의**: 이 견적은 지금 확인한 11페이지 표본 기반이다. 문서 유형별(저학년
빈칸형 vs 중등 인용多형)로 출력 토큰 편차가 커서(160~1,492 토큰) 305건 전체
실행 전 20~30페이지 정도를 더 뽑아 견적을 좁히는 걸 권장한다.

## 4. 방식 B로도 해결되지 않는 항목

1. **원본 이미지(표지·삽화·참고 이미지) 자체 추출** — 이번 프롬프트는 텍스트/표
   구조만 뽑았고, 페이지에서 그림을 잘라 파일로 저장하는 작업은 안 한다. 방식 A는
   이미 이걸 하고 있다(`extracted_images/`, 저해상도 플래그 포함). **B를 도입해도
   이미지 추출은 A의 기존 방식(PyMuPDF 이미지 추출)을 그대로 써야 한다** — 완전
   대체가 아니라 하이브리드가 됨.
2. **O·X 정답·어휘 뜻풀이 (1,210건)** — 같은 학생용 PDF를 읽는 한 B도 정답을
   만들어낼 수 없다(원천에 값이 없음, `SOURCE_DATA_GAPS.md`). 이건 파싱 방식과
   무관하게 교사용 자료·어휘 사전이 별도로 필요하다.
3. **페이지 경계를 넘는 문항** — B는 페이지 단위로 독립 호출하므로, 질문이 다음
   페이지로 넘어가는 경우 자동으로 이어붙지 않는다(위 2절 열하일기 사례의 item3
   `question_text: null`이 이런 상황일 가능성 - 다음 페이지 확인 필요). 별도
   스티칭 로직이 있어야 한다 - A는 애초에 페이지 단위가 아니라 문항 단위로 DB에
   저장돼 있어 이 문제 자체가 없다(다만 A는 컬럼 밀림이라는 자기 문제가 있었다).
4. **layout_hint의 실질 유용성** — 3-4절처럼 프롬프트를 더 세분화해야 기존
   `ui_type`보다 나은 신호가 된다. 이번 표본만으로는 "명확한 개선"이라고 하기
   이르다.
5. **원본 PDF 상시 접근성** — 오늘은 외장 드라이브가 연결돼 있어 305건 전부
   접근 가능했지만, 이 프로젝트에서 이미 "USB/외장 드라이브 연결 안 됨"으로
   재파싱이 막힌 사례(L7-Q1-W08, momo_book_review reparse-upload 기능 참고)가
   있었다 - 305건 전체 재실행 전에 드라이브가 계속 연결된 상태를 유지할 수 있는지
   확인 필요.
6. **경미한 표기 비일관** — 쪽수 인용이 `(127)` / `p.127` / `194`처럼 문서마다
   형식이 다르게 나왔다(방식 A는 DB `evidence_page`/`excerpt_page` 정수 컬럼이라
   항상 일관됨) - B를 쓰면 후처리 정규화 단계가 하나 더 필요하다.

## 5. 요약 판단 (참고용 - 최종 결정은 사용자 몫)

- **기준 1(제시문·질문 분리)·기준 2(어순 뒤섞임)는 방식 B가 명확히 더 낫다** -
  특히 기준 2는 구조적으로 재발 자체가 안 된다(텍스트 레이어 버그를 우회하므로).
- **기준 3(표·목록 구조)도 B가 더 낫다** - A가 스키마 설계상 아예 놓치는 정보
  (어휘 "문장 만들기" 연습 등)를 B는 이미지를 보고 그대로 잡아낸다.
- **기준 4(layout_hint)는 아직 확실한 우위가 아니다** - 프롬프트 재설계가
